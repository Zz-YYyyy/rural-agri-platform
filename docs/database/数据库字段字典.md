## 统一字段约定

| 项目 | 约定 |
| --- | --- |
| 引擎与字符集 | InnoDB，utf8mb4，utf8mb4_bin；身份标识和状态码区分大小写，服务端仍负责 trim 和规范化，不依赖排序规则过滤所有非法输入 |
| 主键 | `id BIGINT AUTO_INCREMENT`，Java 使用 Long，对外 JSON 按字符串传 ID，避免 JavaScript 大整数精度丢失；主键不重用 |
| 关联 | 引用字段也是 BIGINT；本版采用逻辑关联，不声明物理外键。后端负责存在性、归属、状态和删除限制，规则见实现说明 |
| 时间 | DATETIME(3)，精度为毫秒，保存 UTC；应用数据库会话使用 `+00:00`，展示转换为 Asia/Shanghai。接口时间格式在接口契约统一，不向数据库直接写未经转换的本地时间 |
| 创建／更新 | 默认 CURRENT_TIMESTAMP(3) 依赖上述 UTC 会话。可变记录含 updated_at；只追加日志保留独立事件时间。created_at 不等于所有业务的有效时刻 |
| 交易金额 | DECIMAL(12,2)，人民币元；Java 使用 BigDecimal，接口用定点十进制字符串；没有折扣、真实支付或资金结算字段 |
| AI 成本 | DECIMAL(18,8) 保存小额调用费用，币种与计价依据独立记录；未知 token 和金额为 NULL，不用 0 冒充已核实 |
| 数量／标记 | 库存、购买数量按整数份；布尔 TINYINT 限 0/1，具体状态用大写字符串并 CHECK，不以状态码代替角色归属校验 |
| 可空字段 | NULL 表示未填写／尚未发生／未知，具体含义逐字段说明；未填写文本由接口规范为空值，必填字符串在后端校验非空白 |
| JSON | 仅保存有界结构化列表／快照，字段级 CHECK 检查基础形状，元素类型、资源权限及长度由后端校验；不设依赖版本特性的 JSON 非空默认值 |
| 默认值 | 技术默认值不替代发布、付款、退款等业务操作。例如商品默认下架，发布事务完成必要校验后才设置上架 |
| 历史保留 | 订单、退款、库存、参与历史和评价不跟随用户、商品、规格级联删除；没有全表通用逻辑删除标记，按各对象的生命周期处理 |

采用 8.0.16 作为最低语法基线，是因为此前版本可能解析 CHECK 却不执行；目标环境需要实际执行本迁移验证。JSON 默认值与毫秒时间写法也按 MySQL 文档核对。[MySQL CHECK 说明](https://dev.mysql.com/doc/refman/8.0/en/create-table-check-constraints.html)、[默认值说明](https://dev.mysql.com/doc/refman/8.0/en/data-type-defaults.html)、[小数秒说明](https://dev.mysql.com/doc/refman/8.0/en/fractional-seconds.html)。

## 如何维护

本文件下方标记区从 SQL 字段注释生成，防止重复抄写造成漂移。修改尚未应用的 V1 设计时，同步修改 SQL 及实现说明，再运行仓库的 `python scripts/check_database_design.py --write-dictionary`，之后执行不带参数的检查。已部署的 V1 不可重写，后续用 V2 等增量迁移并扩展字典和校验工具；当前检查器只覆盖 V1，不假装已经合并未来迁移。

数据库能强制的唯一性、非空和行内校验列在下方；跨表关系、同时有效记录、权限、幂等内容一致性与生命周期时间窗口由服务层事务落实。字段存在不等于该字段可以由客户端自由提交，响应也不能直接序列化整行。
