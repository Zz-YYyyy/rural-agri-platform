## 3 后端组织建议

采用单体后端，根包为 `com.ruralagri.platform`，已有启动类、config 与 common.web。后续按账号、农户、商品、推广、订单、沟通和 AI 分包，保留清晰服务边界。具体运行命令和版本依据见 [本地开发与运行](../development/本地开发与运行.md)。

首版仅首次农户入驻需要人工审核；商品发布修改、农户资料修改通过服务端校验直接生效，专题报名符合条件自动加入。无需为这些普通操作引入通用审批引擎、资料待审版本或 AI 审核服务。管理员下架和禁用仍按有效业务限制校验，退款争议与超时接手保持已确认的人工处理流程。

本阶段没有选择微服务、消息队列、Elasticsearch 或独立多 Agent 系统作为首版依赖。需要新增基础设施时先说明具体问题及对部署、测试与文档的影响。

## 4 Redis 的使用计划

| 用途 | 业务场景 | 后续必须明确的约束 |
| --- | --- | --- |
| 读取缓存 | 首页推荐、分类、助农专题等重复读取 | 键结构、过期、内容更新后失效、缓存失败处理 |
| 会话状态 | 保存 jti 与账号映射，过期与 2 小时 JWT 对齐；退出撤销当前 jti，不提供刷新 | JWT 仍需校验当前身份；Redis 不可用时受保护请求返回503。会话键见账号运行文档；账号停用拒绝受保护操作，存量业务细分权限仍待明确 |
| 调用频率 | 控制登录尝试、AI 请求及模型费用 | 计数维度、时间窗口、原子性、超限响应和配置 |
| AI 近期上下文 | 保留当前会话近期消息 | 按用户与会话隔离、窗口、过期、并发追加和历史持久化边界 |

完整聊天历史与短期上下文是不同需求，历史是否长期保留以及删除策略仍待确认。Redis 已纳入技术栈不意味着已经选定向量库或 RAG；知识库是后续候选。

## 5 订单与数据一致性约束

- FR-ORDER-003 要求后端创建订单成功时保存金额快照，后续支付、展示与退款依据该订单记录；不能重新联查商品当前价格或农户当前运费来覆盖旧订单。该快照与创建及预占流程保持一致，不延长未付款30分钟期限。

- 依照 FR-INV-001、FR-ORDER-002、FR-REFUND-001，实现订单创建与库存预占一致、付款不重复扣减、取消超时与退款不重复返还。
- FR-REFUND-002 至 FR-REFUND-006 定义农户待审核、24 小时复核窗口及管理员待处理的发货暂停，窗口到期未复核、有效撤回或不退款结果恢复履约权限。
- 48 小时审核超时只生成提醒与人工待办，管理员可接手农户超时申请，不自动退款。接手与原农户审核、撤回与退款、复核与窗口到期均需校验同一有效状态。
- 待处理阶段的开始、流转和结束需要持久化，保留原申请与处理链路；旧阶段任务不能覆盖新阶段，接手也不能抹去原等待时长。
- 处理重复请求、状态竞争、事务失败和任务重试时，不能只依靠前端禁用按钮。
- 待付款超时以持久化创建或截止时间判定，后台识别过期订单，不仅依赖内存计时或 Redis 过期通知。
- 库存和退款流水、唯一约束、事务边界和幂等策略在数据库与接口设计中共同明确，不在当前图示中虚构既成结构。

## 6 AI 调用边界

现行客户端协议为普通 JSON 的异步接受＋轮询，首版不使用流式响应：提交提问后返回202及 requestId，前端按 pollAfterMs 查询原请求，完成、失败或拒绝后停止，页面后台暂停。后端持久化消息后由受控执行器调用模型和商品工具，再校验结果并更新原回复；数据库事务不等待模型，同一请求重试不新开收费调用。细节见 [沟通与AI接口](../api/沟通与AI接口.md)。

本轮接口容量设计：输入最多1000字符、回答文本最多16000字符、最多6张核验后的商品卡片；同一会话最多一个进行中的回答。这些设计不等于模型 token 或费用上限，也不表示同账号跨会话的并发配额已确定。

价格、库存和交易状态通过业务查询与正常交易接口处理。模型没有数据库账号或任意 SQL 执行能力，不能自行声明付款或创建越权订单。

提示词、工具说明、上下文和结构化输出仍需工程实现与验证；回答中的商品事实须有平台资料支持。无结果、固定拒绝、失败与历史卡片重校验已有契约，具体模型超时、内部重试、token 配额及上下文窗口仍需配置；未知用量保留预算占用，不能按零释放。

用户计划使用中转站 API，要求控制费用并避免模块被当成任意任务代理。已确认发送消息必须登录、首版不设个人每日固定次数，同时保留短时防刷、单次消耗与平台总预算保护。具体候选方案见 [AI 导购业务边界与费用控制](AI导购与控费方案.md)，内部调用、token、频率和预算等参数仍待确认；仅使用系统提示词不能代替服务端业务与费用约束。
