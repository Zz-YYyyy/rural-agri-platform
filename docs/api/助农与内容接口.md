# 助农、内容与推广反馈接口

状态：2026-11-20 首版接口设计，尚无 HTTP 服务或联调结果。完整路径、参数位置、DTO 类型／必填／长度／枚举及响应定义维护在 [助农与内容契约分片](分模块契约/助农与内容.json)，可导入的合并文件由总入口提供。全局鉴权、金额／时间、分页和错误包络见 [接口文档](接口文档.md)。

本模块承接已确定的助农专题、单商品主动推广、产地介绍、农户主页故事和浏览／咨询反馈。对应 FR-PROMO-001 至 FR-PROMO-033、FR-CONTENT-001；关系与时钟解释见 [数据库实现与迁移说明](../database/数据库实现与迁移说明.md)。专题和主动助农信息是两个独立对象，报名不建立第二套商品价格库存，发布／报名不产生订单或占用库存。

## 2 专题发布、展示和参与

管理员创建草稿可传 `{}`；后端创建 `DRAFT` 和版本 0，不产生公开内容。保存草稿使用完整替换 DTO：标题、介绍、起止、地区／分类、封面均明确传入，`null` 表示未填写或不限；已填写值仍校验格式，开始与结束同时存在时要求开始早于结束。

发布携带当前 `expectedVersion`。服务端取发布有效时刻 P，要求标题、普通文字介绍和 S/E 齐全，`S < E` 且 `P < E`。允许 `S <= P`，发布后立即进入进行中；时间与产地／分类条件从首次有效发布后固定，不回填此前的展示或报名。封面可为空，由服务端返回默认图 URL。

发布后的普通编辑使用单独的说明 DTO，只允许标题、介绍、封面，原时间与条件不在输入模型中。通过把旧草稿对象整体提交给已发布专题，不能覆盖这些固定字段。创建、发布和管理操作同事务保存审计日志；首次发布时间和结束时间不因重复提交变化。

| 返回字段 | 含义 |
| --- | --- |
| `publicationStatus` | 管理端持久化发布状态：DRAFT / PUBLISHED |
| `stage` | 即时计算的 DRAFT / UPCOMING / ACTIVE / ENDED / ENDED_EARLY；公开响应不出现 DRAFT |
| `isHidden` | 管理端看到的独立整体隐藏状态，不是生命周期阶段 |
| `plannedStartAt / plannedEndAt` | 首次发布后固定的原计划时间 |
| `effectiveEndAt` | 首次有效提前结束时间，或自然结束时的原计划截止；未结束为空 |
| `enrollmentOpen` | 专题目前处于允许报名的时间和公开状态；具体商品仍须再次校验 |

公开列表只列指定的预告或进行中阶段；历史从原详情链接访问。详情介绍与商品分页分开读取，避免一次返回全部商品。专题草稿或整体隐藏时公开详情返回 404，响应不泄漏原介绍、参与列表或管理原因。预告商品分页为空，不提前报名。

报名每次传一个 `productId`，首次 `expectedEventSeq=0`；已退出或已移出的关系合法重报时传它当前的事件序号。一个农户可参加多个商品，一个商品也可独立参与多个专题，均复用原商品价格库存。商品需要归属于当前农户、正常上架、经营有效，满足专题地区与分类限制；两个条件同时设置时取交集，所选节点包含自身及下级。全部规格缺货仍可报名、展示和咨询，购买必须由订单流程校验库存。

参与关系使用 `JOINED / EXITED / REMOVED`，与当前可见性分离。商品主动下架或产地／分类变得不匹配时，仍保留 `JOINED`，只是当前展示暂隐藏；满足条件并仍在有效专题中才恢复。`displayState` 用于界面展示，不给客户端授予直接修改关系状态的权限。

退出操作同时核对关系 ID、`participationRound` 和 `expectedEventSeq`。管理员移出保存 `REMOVED`、定向禁报标记和对应的 `blockedEventSeq`；解除操作必须指向这一次限制，解除后仍为 REMOVED，农户再次主动报名才进入新一轮。旧退出请求不能退出新的参与轮次，旧解除请求不能清除后来新设的限制。

管理员提前结束仅在进行中生效，原因必填；原计划起止保持，保存有效截止和当时的参与事实，不允许重开。整体隐藏适用于预告、进行中和已结束专题，时间继续运行；解除后按当前阶段恢复，已结束的只恢复历史页。上述操作不下架商品、不修改其他专题或已有订单咨询。

## 3 历史成员与未决情形的明确边界

正常专题历史依照有效截止时未退出、未被移除的参与事实定位；此前退出／移除但截止前已经合法重报的，按最后有效一轮判断。仅商品主动下架造成暂隐藏的原保留参与，按已确认规则保留历史资格，具体商品入口仍校验当前公开性。商品卡片价格、库存、公开名称采用当前值，不能把当前值解释成结束时价格快照或成交结果。

产地／分类不匹配隐藏的参与是否纳入结束历史仍未确认。相关事实已经保存在参与事件和结束快照中，但本轮不静默选定纳入／排除。某专题的历史成员查询触及此分支时返回 503 `POLICY_PENDING`，专题介绍仍可读取；业务规则补齐后必须同步契约、需求与验收，再开放这一分支。

整体隐藏期间是否可编辑说明、退出、提前结束，以及结束后进一步参与管理范围仍待确认。相应操作在 JSON 中带 `x-pending-policy`；正常已确认主流程可以开发，未决交叉情形暂不执行。全平台账号／经营禁用解除不自动等价于恢复专题或内容权限。

## 4 主动助农信息

发布一条信息关联一个自家正常上架商品，标题和普通文字说明必填。供货说明和买家类型选填；`buyerType` 为 HOUSEHOLD / BULK / BOTH 或 null，不由此生成采购意向单或不同价格。商品图、价格、产地与库存复用原商品，不重新填写或保存一个可独立交易的副本。

首次有效发布时间由后端确定，要求 `publishedAt < deadlineAt <= publishedAt + 30×24小时`。同商品最多一条未结束记录，暂隐藏也占名额。自然结束按原截止、主动结束按首次成功时刻起算 7×24 小时，等待期满才可提交新记录；新一轮使用新幂等键，旧记录不复活。

创建的 `Idempotency-Key` 映射 `assistance_post.request_id`，`request_fingerprint` 保存首次规范化输入摘要，编辑不改变该摘要。同农户同键同摘要返回已有记录的当前详情，同键不同摘要拒绝。原创建输入与当前已编辑文本可能不同，不能直接拿当前文本代替原请求摘要做重试判断。

普通编辑只完整替换标题、推广说明、供货说明和买家类型，并核对 `expectedVersion`。两个可选项显式传 null 才清空；不能改变商品、首次发布时间或截止。旧版本提交返回 409，不自动覆盖新版本。结束操作保留原说明和期限，仅首次确定正常结束事实，重试不改变结束时间或等待期。

未结束信息因商品主动下架暂隐藏时，公开旧链接返回 404 并禁止从本条新咨询。正常结束的历史仍可显示原推广说明，`canConsultFromPost=false`；当前允许访问的商品和农户可继续跳转。结束历史与商品下架叠加、隐藏期间编辑／提前结束及管理限制联动仍列为未决分支，不能从历史保留推导为永久公开或扩大权限。

## 5 图文与资源投影

本轮沿用一地区一份产地介绍、一农户主页一份故事的实现方式。产地内容由管理员维护，农户仅维护自己故事；输入为公共 `ContentBlock`：

```json
[
  {"type":"text","text":"这里填写种植者提供的种植环境介绍。"},
  {"type":"image","key":"uploads/story/demo.jpg"}
]
```

服务端校验资源来自受控上传、操作者有权使用、块类型白名单、单文字块最多 1000 字符、总文字最多 10000 字符、至多 50 块及 20 张图片。公开投影的图片块为 `{"type":"image","url":"https://example.invalid/assets/origin.jpg"}`，文字按纯文字渲染，不执行 HTML。公开农户故事随农户主页接口返回；本模块的 `/farmer/story` 是本人编辑接口，不公开经营手机号。

没有故事不影响入驻或购物。尚未填写时读取返回空数组；已有内容的撤下、删除、恢复权限未确定，因此写入口只接受至少一个有效块，不借清空 PUT 偷偷提供删除能力。产地编辑保留原地区和首次发布时间；不增加审核、社区评论或文章列表。

## 6 推广统计与来源

公开专题／助农详情及账号商品模块的农户／商品详情接受可选 `X-Visitor-Id`，值为客户端随机 UUID，只用于匿名去重。有有效登录时用账号 ID，忽略匿名值；无有效标识时仍允许浏览，但不伪造一条访客事件。公开读取携带已失效的可选凭证时按游客处理，不使用该凭证归属统计；受保护接口仍严格校验登录。图片等静态资源请求、列表分页和预加载未成功显示的页面不直接当作详情访问。

推广事件由成功公开详情读取或成功保存的有来源咨询消息产生，不提供客户端任意填计数的接口。普通详情 GET 是否用于界面预加载由调用方区分：计数型详情读取只在真正打开对应详情时调用，预加载使用列表卡片，不因后台反复预取伪造浏览。

`VIEW` 按同一账号／匿名访客、同一直接来源对象、同一 UTC 30 分钟桶去重；`CONSULT` 按成功保存且来源有效的买家消息计数，农户回复和 DIRECT 续聊不算。专题页未指向具体商品／农户的浏览只记平台专题，不平均分配给所有参与者。商品详情带专题或助农来源时由商品模块验证直接关系，只记该直接来源，不把商品同时参加的所有专题都算一次。

本轮补充计数实施选择：登录农户查看自家详情不计本人推广浏览；匿名无法可靠识别真实身份，仍按随机访客口径。演示流量保留并明确标为演示数据，不宣称真实经营成果。这些是实现口径，不是对用户作出的历史业务确认，也不保证跨设备去重或精准反作弊。

报表必须传 `startDate / endDate`（Asia/Shanghai，起止都包含），区间最多 90 个自然日，服务器换算 UTC 半开区间。按天补齐零值并升序，返回生成时刻；首版 SQL 按已提交事件实时聚合，无每日任务等待。农户查询范围固定为本人，管理员可选一个农户或查平台汇总；均不返回访客身份、完整咨询内容或虚构收入。

## 7 幂等、版本与错误处理

| 操作类别 | 实现约束 |
| --- | --- |
| 管理员创建／更新／发布／隐藏／恢复 | 使用 Idempotency-Key；管理员 ID＋动作＋键规范化哈希映射 admin_operation_log.operation_id，同事务记录目标与请求摘要；同键核对语义后重放，不创建重复专题或改变首次结果 |
| 专题加入／退出／移除／解限 | operation_key 与当前关系、参与轮次、eventSeq 配合；旧请求重试先识别原事件，不能作用于后来的新一轮 |
| 助农发布 | 同农户 request_id 唯一，request_fingerprint 保留原始输入语义，普通编辑不改摘要 |
| 助农说明编辑 | 完整 PUT＋expectedVersion；版本过期返回冲突，由前端读取新值再决定后续提交 |
| 助农结束 | 首次结束事实＋版本及商品锁；自然到期补判不改成主动结束，不重复延后重发起点 |
| 农户故事 | 完整 PUT，原子更新本人 story_content；重复相同内容不新增对象或审核，不声称具有未设计的通用幂等表 |

关键业务错误均使用统一 ErrorResponse，不以 HTTP 200 包裹失败。除通用参数、鉴权及依赖异常外，本模块使用以下代码：

| HTTP / 代码 | 客户端处理 |
| --- | --- |
| 404 RESOURCE_UNAVAILABLE | 显示暂不可用；不要展示缓存中的草稿、隐藏或受限详情 |
| 409 STATE_CONFLICT | 刷新详情，按当前阶段展示允许操作 |
| 409 VERSION_CONFLICT | 刷新版本或参与事件序号，不自动覆盖当前状态 |
| 409 IDEMPOTENCY_CONFLICT | 原键对应不同请求；禁止自动换键盲目再次提交 |
| 409 PARTICIPATION_INELIGIBLE | 展示不符合的条件，正常下架或归属等限制不能通过重试绕过 |
| 409 ALREADY_PARTICIPATING / CAMPAIGN_JOIN_BLOCKED | 显示已参与或管理员限制，不建立第二份参与 |
| 409 ACTIVE_PROMOTION_EXISTS / PROMOTION_COOLDOWN | 展示当前记录或正常结束后的最早重发时间 |
| 400 INVALID_DEADLINE | 按服务端时刻重新选择有效截止；不改写首次发布时间 |
| 409 ORIGIN_ALREADY_EXISTS | 打开该地区现有介绍进行编辑 |
| 503 POLICY_PENDING | 该交叉情形尚未开放；保留事实和原数据，不伪造成功结果 |

## 8 开发与验收追踪

每个 OpenAPI operation 的 `x-requirements`、`x-acceptance`、`x-tables` 对应需求、既有验收场景和真实表；`x-errors` 给出核心错误，`x-pending-policy` 标记未决交叉情形。静态检查通过只说明契约结构、引用和文档可核对，不代表这些接口已经实现或 AC 已执行。

优先联调：创建草稿并发布 → 农户报名 → 公开详情选购；退出重报及管理移除解限；主动推广创建 → 编辑 → 正常结束 → 验证七天重发；本人故事与产地介绍；带来源浏览／留言 → 本人和平台汇总。时间与权限核心用例必须由后端事务校验，不能仅靠前端隐藏按钮。
