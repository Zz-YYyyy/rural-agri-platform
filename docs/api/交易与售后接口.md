# 交易与售后接口

版本：V1 接口设计，2026-11-20。适用微信小程序、H5 和网页管理端；接口尚未实现或联调。完整字段、必填、枚举、长度和示例见 [分模块契约](分模块契约/交易与售后.json)，公共鉴权、错误包络和维护方式见 [接口文档](接口文档.md)。

## 阅读与调用约定

- 以下路径均包含 `/api/v1`；JSON 请求使用 `Content-Type: application/json`。MEMBER 为当前登录账号，FARMER 必须具备当前有效经营身份且只能操作本人销售业务，ADMIN 是已授权统一管理员。公共评价不要求登录。
- 成功 HTTP 200，响应统一为 `code/message/data/traceId`；表格中的响应是 `data` 类型。分页默认第 1 页、每页 20，最大 100；列表均写明稳定排序。
- 所有 ID 是十进制字符串，金额是元且固定两位小数字符串，时间为 UTC ISO 8601 毫秒；未发生的可选事实字段省略。真实交易未接入，模拟订单、支付、退款和物流必须明确标记。
- `Idempotency-Key` 标为必需的操作，客户端为一次明确动作生成唯一键并在网络重试时复用。新一次退款申请使用新键；同键不同输入返回 `IDEMPOTENCY_CONFLICT`。客户端不能通过换键重新扣库存或重复退款。
- 已确认提交前单价或运费变化时先提示并刷新报价，待用户再次确认后才创建订单（FR-ORDER-007）。返回 `PRICE_CHANGED` 后重调报价接口，展示新价，再用新键提交；原成功建单的同键重试仍返回原订单，不重新定价。其他标记 `x-pending-policy` 的特殊权限分支保持待定，不冒充完整闭合的业务规则。

## 每项操作的业务效果与错误

### 我的收藏

`GET /api/v1/me/favorites` · `listMyFavorites`

只查询当前账号；按createdAt降序、id降序。不可见商品返回不可用标记，不泄露其当前内容。

查询参数：`page`（页码，从1开始）、`pageSize`（每页条数）。

依据：FR-UI-002；验收关联：AC-UI-003。

### 收藏商品

`PUT /api/v1/me/favorites/{productId}` · `saveMyFavorite`

商品当前须允许公开访问；唯一(user_id,product_id)，已收藏重复请求仍成功。缺货不阻止收藏，不占库存。

主要业务错误：HTTP 404 `PRODUCT_NOT_VISIBLE`：商品当前不可访问。

依据：FR-UI-002；验收关联：AC-UI-003。

### 取消收藏

`DELETE /api/v1/me/favorites/{productId}` · `removeMyFavorite`

只删除本人收藏；已经不存在仍返回成功。与商品、订单、其他用户收藏无关。

依据：FR-UI-002；验收关联：AC-UI-003。

### 购物车明细

`GET /api/v1/me/cart-items` · `listMyCart`

按farmerId分组展示，服务端按updatedAt降序、id降序分页。购物车不锁价、不占库存；页面先读取再按目标份数设置。

查询参数：`page`（页码，从1开始）、`pageSize`（每页条数）。

依据：FR-CART-001；验收关联：AC-CART-001。

### 设置购物车规格份数

`PUT /api/v1/me/cart-items/{skuId}` · `setMyCartQuantity`

只写本人该规格的目标总份数，无记录时创建，有记录时替换quantity；多个页面最后一次有效保存生效。新添加须商品可购买且规格有效；库存不足时保留原记录并返回错误。相同目标重试不增加份数。

主要业务错误：HTTP 409 `PRODUCT_UNAVAILABLE`：商品、规格或经营身份不允许新购买；HTTP 409 `INSUFFICIENT_STOCK`：规格当前可售库存不足，整笔创建回滚。

依据：FR-CART-001、FR-PRODUCT-004；验收关联：AC-CART-001、AC-PRODUCT-008。

### 移除购物车规格

`DELETE /api/v1/me/cart-items/{skuId}` · `removeMyCartItem`

删除本人规格记录；已不存在仍成功。不删除商品、不影响订单或库存。

依据：FR-CART-001；验收关联：AC-CART-001。

### 确认页计算报价

`POST /api/v1/me/order-quotes` · `quoteMyOrder`

校验商品规格均属于一个指定农户且允许新购买，合并相同SKU后计算金额、固定运费和当前可售库存；不占用库存、不生成订单、不承诺价格有效期。

主要业务错误：HTTP 409 `PRODUCT_UNAVAILABLE`：商品、规格或经营身份不允许新购买；HTTP 409 `INSUFFICIENT_STOCK`：规格当前可售库存不足，整笔创建回滚。

依据：FR-CART-001、FR-SHIP-001、FR-ORDER-003；验收关联：AC-CART-001、AC-ORDER-001。

### 创建单农户订单

`POST /api/v1/me/orders` · `createMyOrder`

校验登录与一个农户、最多50个合并规格；重复SKU的确认单价必须一致，否则参数错误。Idempotency-Key映射trade_order.client_request_id；原始请求摘要包含用户确认的单价和运费，重试先查已成功结果，不重新定价。新请求在事务中按SKU升序锁定、校验当前价与确认单价/运费相等、库存充足，保存金额地址快照并扣可售库存、写库存和订单日志；30分钟期限从有效createdAt起算。任一失败整体回滚。任一单价或运费变化都返回PRICE_CHANGED，不建单、不占库存；页面重新调用报价接口，展示新价，用户再次确认后使用新幂等键提交。失败请求未留下有效订单；原键同输入重试仍校验当前条件，不把失败当成成功幂等结果。金额溢出拒绝。创建不自动删除购物车，成功后页面可对本次已结算规格调用购物车删除。

主要业务错误：HTTP 409 `PRODUCT_UNAVAILABLE`：商品、规格或经营身份不允许新购买；HTTP 409 `INSUFFICIENT_STOCK`：规格当前可售库存不足，整笔创建回滚；HTTP 409 `PRICE_CHANGED`：单价或运费已变化，请重新获取报价并确认；HTTP 409 `IDEMPOTENCY_CONFLICT`：相同幂等键对应不同目标或输入；HTTP 400 `AMOUNT_OUT_OF_RANGE`：整单金额超出DECIMAL(12,2)范围。

依据：FR-CART-001、FR-ORDER-001、FR-ORDER-002、FR-ORDER-003、FR-ORDER-004、FR-ORDER-005、FR-ORDER-007、FR-INV-001；验收关联：AC-ORDER-001、AC-ORDER-005、AC-INV-001、AC-ORDER-024、AC-ORDER-025、AC-ORDER-026。

### 买家订单列表

`GET /api/v1/me/orders` · `listMeOrders`

按trade_order.user_id等于当前账号限制结果，createdAt降序、id降序。退款待处理仍是待发货订单，不能按订单状态代替退款筛选。

查询参数：`page`（页码，从1开始）、`pageSize`（每页条数）、`status`（可选履约状态）。

依据：FR-ORDER-001、FR-FARM-002；验收关联：AC-ORDER-001、AC-FARM-001。

### 买家订单详情

`GET /api/v1/me/orders/{orderId}` · `getMeOrder`

必须满足trade_order.user_id等于当前账号；越权视为不可见。返回历史金额地址、当前可操作标记和真实模拟节点，未发生事实省略；动作资格按服务端时间重新计算。

依据：FR-ORDER-001、FR-ORDER-003、FR-ORDER-004、FR-SHIP-002；验收关联：AC-ORDER-001、AC-ORDER-006、AC-SHIP-007。

### 买家订单业务记录

`GET /api/v1/me/orders/{orderId}/events` · `listMeOrderEvents`

满足trade_order.user_id等于当前账号；仅返回允许对订单双方展示的有效节点与原因，按occurredAt、id升序。使用分页，前端可加载全部。不返回内部event_data与管理员身份资料。

查询参数：`page`（页码，从1开始）、`pageSize`（每页条数）。

依据：FR-ORDER-001、FR-REFUND-003、FR-REFUND-006；验收关联：AC-SHIP-007、AC-REFUND-018。

### 买家订单退款历史

`GET /api/v1/me/orders/{orderId}/refunds` · `listMeOrderRefunds`

满足trade_order.user_id等于当前账号；按createdAt降序、id降序返回多轮申请，保留已撤回与拒绝记录；同订单只有一轮活动流程。

查询参数：`page`（页码，从1开始）、`pageSize`（每页条数）。

依据：FR-REFUND-003、FR-REFUND-005、FR-REFUND-007；验收关联：AC-REFUND-014、AC-REFUND-015。

### 申请或重新申请整单退款

`POST /api/v1/me/orders/{orderId}/refunds` · `applyMyOrderRefund`

锁本人已付款未发货订单；检查无活动退款且从未成功退款。允许前轮WITHDRAWN或最终REJECTED结束后以新的Idempotency-Key重申，生成新记录；原申请重试先以(user_id,client_request_id)与摘要查重，不能算新轮次。当前时间已过旧复核窗口时先将旧轮收敛终态再校验。金额取原paidAmount，申请不返库存，形成FARMER_PENDING并暂停发货；与发货竞争只成功一方。

主要业务错误：HTTP 409 `STATE_CONFLICT`：当前业务状态已变化，请刷新；不执行旧状态操作；HTTP 409 `IDEMPOTENCY_CONFLICT`：相同幂等键对应不同目标或输入；HTTP 409 `ACTIVE_REFUND_EXISTS`：已有待处理退款或有效复核窗口；HTTP 409 `ORDER_ALREADY_REFUNDED`：整单已退款成功，不能再次退款。

依据：FR-REFUND-001、FR-REFUND-002、FR-REFUND-007；验收关联：AC-REFUND-006、AC-REFUND-022、AC-REFUND-023、AC-REFUND-024。

## 订单与退款状态配合

| 订单状态 | 允许的核心操作 | 库存效果 |
| --- | --- | --- |
| PENDING_PAYMENT | 原30分钟内付款、改地址；未付取消或超时关闭 | 下单已扣可售库存；关闭整单返还一次 |
| PENDING_SHIPMENT | 正常发货；发货前申请整单退款 | 申请和拒绝不返还；退款成功才返还 |
| PENDING_RECEIPT | 买家确认或发货7天后系统确认 | 不再扣减或返还 |
| COMPLETED | 实际完成后30天内自愿首次评价 | 不改变库存 |
| CLOSED / REFUNDED | 只读原记录，禁止复活订单 | 已返还，重复请求不再返还 |

`FARMER_PENDING`、有效 `APPEAL_WINDOW` 和 `ADMIN_PENDING` 均暂停发货；超过48小时只进入人工待办。窗口到期、有效撤回或最终拒绝解除本轮暂停，但发货仍核对所有其他权限。2026-11-20 已确认允许再次申请：必须仍已付款、未发货且没有活动申请，整单最多成功退款一次。重申生成新记录，旧拒绝和撤回不被覆盖。

所有订单、库存、退款操作由 MySQL 事务和订单／SKU 行锁保护。退款成功需同事务更新订单、明细返还标记、可售库存、库存流水、退款结果及业务日志；管理员动作另记管理日志。退款与发货竞争，先获得有效结果的一方决定后续可操作性。

| 动作 | 已有存储依据 | 重试规则 |
| --- | --- | --- |
| 创建订单／申请退款 | user_id + client_request_id 唯一键、request_fingerprint | 同请求返回原记录；不同输入拒绝；原订单改址不改变最初请求摘要 |
| 付款／取消／改址／发货／收货／退款阶段动作 | order_action_log.business_key；必要请求摘要放白名单event_data | 对动作、操作者、目标和幂等键做规范化SHA-256；查到原有效动作先返回该对象现状，不重新更新或返回过时快照 |
| 评价／一次回复 | order_review.order_id唯一、回复只能从空变为一次有效值 | 原内容一致的重试返回回执；不同内容不能变成改评或改回复 |
| 评价隐藏／恢复 | admin_operation_log.operation_id及脱敏changes中的请求摘要 | 同键重试不覆盖后来处置；新操作用新键，保留每次原因 |
| 收藏／购物车目标数量 | 用户商品／用户SKU唯一键与PUT目标状态 | 相同目标重复执行效果不叠加；删除已不存在记录仍成功 |

## 下单调用示例

下面是演示数据，不包含真实收货人或运行地址。先报价，展示服务端返回的单价和运费，再发创建请求。

```http
POST /api/v1/me/orders
Content-Type: application/json
Authorization: Bearer <access-token>
Idempotency-Key: demo-checkout-20261120-001
```

```json
{
  "farmerId": "11",
  "items": [
    {
      "skuId": "301",
      "quantity": 2,
      "confirmedUnitPrice": "30.00"
    }
  ],
  "confirmedShippingAmount": "6.00",
  "address": {
    "recipientName": "演示收件人",
    "recipientPhone": "13800000000",
    "regionId": "500101",
    "detailAddress": "演示村示例路1号"
  },
  "buyerRemark": "请加固包装"
}
```

成功的 `data` 包含订单 `id`、原金额、`paymentDeadline` 和地址／商品快照；客户端之后付款只提交订单 ID，不提交付款金额。网络超时应复用同幂等键查询／重试，不能先假设失败再生成第二单。

## 仍未开放的边界

管理员敏感收货资料查询、经营禁用后的存量履约、规格停用后的旧单支付、隐藏评价在私有页的正文访问和首次回复等，仍按对应 Q 问题单处理。现有正常主流程与已授权管理操作已给出契约；这些特殊情形需要确认后再更新接口，不能从数据库有状态字段推导全部权限。
