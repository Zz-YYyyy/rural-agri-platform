# 接口设计编写要求

状态：已建立覆盖范围与详细编写要求，具体接口尚未设计。最近整理：2026-11-18。

本文件用于指导后续接口设计，**不是可以直接调用的接口清单**。目前没有最终请求路径、DTO 字段、业务错误码或 OpenAPI 文件；不能据此声称前后端已经完成联调。

## 1 设计依据与交付物

接口以 [需求确认稿](../requirements/需求文档.md) 为业务依据，结合 [待确认问题](../requirements/待确认问题.md)、[数据库设计](../database/数据库设计.md) 和 [验收场景](../testing/验收场景清单.md) 共同设计。

本目录后续需要具备机器可读取的 OpenAPI 契约，以及解释业务流程、权限、状态和异常的中文说明。Swagger UI 用于查看与调试，运行时生成的页面不能代替完整的业务解释。契约存放位置、生成或维护方式及兼容版本在工程初始化阶段确定。

## 2 每个接口必须写清的内容

| 项目 | 详细要求 |
| --- | --- |
| 功能与来源 | 接口名称、目的、所属模块、关联 FR 需求、相关页面与验收编号 |
| 请求定位 | HTTP 方法、完整路径、环境基础地址的配置方式、Content-Type；区分路径、查询、请求头和请求体参数 |
| 身份与权限 | 是否允许游客、要求的账号或经营身份、管理员权限、如何确认数据属于当前操作者 |
| 前置条件 | 允许的业务状态、资料要求、库存或时效要求、依赖的其他记录 |
| 请求参数 | 字段含义、类型、必填条件、范围、格式、单位、枚举、默认值，以及空值与未传的区别 |
| 成功响应 | 响应包络、字段定义、可空含义、状态枚举、列表顺序、分页和时间金额约定 |
| 业务效果 | 读取或修改哪些数据，状态如何变化，是否影响库存、模拟金额、未读数、缓存或审计记录 |
| 失败响应 | 鉴权失败、越权、参数不合法、记录不存在、状态冲突及外部调用失败；区分 HTTP 状态与业务错误 |
| 重试与并发 | 重复提交如何识别、是否可安全重试、并发竞争结果、失败后是否已发生业务效果 |
| 完整示例 | 可理解的成功与失败请求响应，说明示例前提；使用虚构演示资料和密钥占位值 |

不能只写“返回成功”或“按之前讨论处理”。例如下单必须说明成功后是否已经预占库存、失败是否留下有效订单，而不仅是返回订单编号。

| 农户 | 首次入驻申请与审核结果、单一经营身份、最小资料及直接更新、经营设置 | FR-FARM-001 至 FR-FARM-004、FR-SHIP-001 |

| 推广反馈 | 农户查看自己的推广反馈，管理员查看平台汇总，首版覆盖浏览和咨询，区分关注与需求反馈 | FR-PROMO-003；计数、去重、时间和来源归属仍待 Q-PROMO-001 |

| 模拟发货 | 订单所属农户选择模拟承运方、确认发货时生成演示单号、展示发货及确认收货节点，区分用户与系统确认来源 | FR-SHIP-002、FR-ORDER-006；发货同时受 FR-REFUND-002 至 FR-REFUND-006 约束 |

| 库存与退款 | 下单预占、状态变更与返还、农户按增减份数调整可售库存；整单退款、农户审核、窗口内管理员复核、待处理撤回、超时待办及人工接手 | FR-INV-001、FR-INV-002、FR-REFUND-001 至 FR-REFUND-006 |
| 站内留言 | 异步文字留言、农户回复、会话读取与未读；普通咨询和特殊批量需求共用已有留言能力 | FR-COMM-001、FR-COMM-002 |
| AI 导购 | 登录用户会话、多轮消息、受控商品查询、卡片校验、业务边界和费用控制；首版不设个人每日固定次数 | FR-AI-001 至 FR-AI-007；具体控制参数待确认 |
| 管理端 | 已批准的审核、运营、订单管理，以及评价／回复隐藏与恢复、原因及重要操作记录 | FR-ROLE-001、FR-REVIEW-007；其余动作见 Q-ADMIN-001 |

收藏、地址簿具体管理和数量上限、搜索排序等页面候选能力仍需逐项确认操作与字段，不能只因出现在页面讨论稿就视为完整接口规格。订单收货信息的四项内容、保存方式与改动时机已经由 FR-ORDER-004 确认，不再归入未定的地址簿细节。

首次入驻仅要求名称、经营地区、主营品类、联系手机号，简介及封面图选填；不能在 DTO 中另加未确认的必填证件、资质或联系人姓名。一个账号最多对应一个农户身份，不能靠修改请求中的农户 ID 切换到他人数据。资料、商品和专题的免人工审核规则不取消后端校验及管理员管理限制。

### 商品资料与规格接口的已确认输入边界

依据 FR-PRODUCT-003，商品发布必填名称、分类、产地、至少 1 张图片、简短介绍，以及至少 1 个包含名称、价格、库存的规格。储存方式和应季月份选填，不得因这两项未填写而阻止其他有效资料发布。字段长度、图片上限与格式等具体校验仍需设计，不能将“至少 1 张”误写成已经确定最大图片数量。

依据 FR-PRODUCT-004，规格使用手工列表，农户逐项填写“3 斤装”“5 斤装”等名称与各自价格、库存；只有一种时使用默认规格。首版不要求先定义重量、等级等属性轴，也不由接口自动生成属性组合。价格针对一份规格包装，购买数量及库存按该规格的份数解释，不能把“3 斤装”的库存 10 份当成 10 斤。

接口需明确商品与规格的所属关系及实际选中规格。单规格商品仍进入相同的规格价格、库存与下单流程，不另设绕过规格的商品级价格扣库存入口。规格增删对购物车和既有订单的影响仍待 Q-PRODUCT-001，不能随手工列表方案默认物理删除已被引用的规格。

### 专题草稿、主动发布与发布后说明编辑

依据 FR-PROMO-022，管理员可先保存尚未填写完整的专题草稿，之后继续补充，资料补齐并通过发布校验后主动发布。草稿只在有权限的管理端可见，不能进入公开专题内容或接受农户报名；已填写资料仍需按后续设计校验，不能把允许未完整草稿理解为任意非法内容都可保存。草稿最低保存字段、管理员间的归属权限与删除能力仍待明确，不提前要求草稿具有全部正式发布字段。

发布由有权限的管理员主动执行，不增加另一位管理员二次审批，也不因到达设定开始时间自动发布草稿。发布成功后仍按原设定的开始和结束时间判断报名资格，不从发布操作重新开始计时；开始前不接受报名的规则不变。发布失败不能产生已公开的半成品或有效报名对象。重复发布不创建另一专题、不刷新起止时间；旧草稿保存与发布并发时须检查服务端当前状态，不能用旧表单覆盖已发布内容或将其退回草稿。

依据 FR-PROMO-023，专题已经发布但尚未结束时，可修改标题、介绍等说明类内容；具体字段范围与输入格式后续设计。起止时间、商品产地与分类报名限制从有效发布起固定，即使尚未开始也不能通过普通编辑修改，不得用“不限”与具体限制之间的切换绕过。后端按实际状态限制可修改字段，不能直接接受客户端完整专题对象覆盖固定值；说明修改与发布／到期交错时，旧请求不能重开专题或把固定字段回写为旧值。

需要不同起止时间或报名条件时，管理员另建专题，原专题和原参与关系继续按原规则处理，不自动迁移、复制参与或把原商品批量报名到新专题。普通编辑不开放已结束专题的说明修改或重新开启；进行中专题的管理员提前结束、已发布专题的整体隐藏与解除分别按 FR-PROMO-026、FR-PROMO-027 执行，不能借说明编辑绕过其操作条件。商品改产地／分类对进行中参与的联动按 FR-PROMO-033；新增不匹配情形的历史影响及结束后内容维护等仍待设计。发布后管理员普通改条件的方案已不采用，不再作为存量联动候选。

依据 FR-PROMO-025，已发布、尚未开始且当前允许公开的专题提供公开预告，用户和农户可查看介绍、原计划开始及结束时间，并明确显示“即将开始”。预告不接受提前报名或预先占位；草稿和整体隐藏专题仍不公开。时间合法性按 FR-PROMO-029 校验，开始已过但结束未到时发布直接进入进行中；草稿最低字段与权限及其他管理细项仍待 Q-CAMPAIGN-001，不从预告推定自动发布或提前报名。

### 专题正式发布资料与时间校验

依据 FR-PROMO-028，正式发布必填标题、普通文字介绍、计划开始与结束，封面图选填，未上传时使用统一默认图；产地及分类继续分别可不限。应区分保存不完整草稿与正式发布校验，不能让缺少必填资料的专题发布，也不能强迫所有草稿保存完整发布数据。介绍按普通文字输入输出，不新增富文本或必交附件；文本长度、图片格式大小、默认图引用及字段空值形式留待正式契约设计。

封面未传是合法情况，不生成虚假的上传记录；若传入封面引用，须检查其有效性及使用权限。默认图由后端统一返回或前端统一回退的具体方式未定，相关端应具有一致显示效果。

依据 FR-PROMO-029，设原计划开始为 S、结束为 E、服务端有效发布时刻为 P，需同时满足 S < E 且 P < E。P < S 时发布为预告；S <= P < E 时允许发布并从成功发布后进入进行中，不修改原计划时间，不补录 S 至 P 之间的报名、公开展示或统计。必须保留真实发布事实，不能用计划开始充当实际发布时间。

E <= P、开始不早于结束、必填日期缺失或格式非法时不允许首次发布；保留草稿供修改后重试，不自动改期、不发布成已结束历史。先前打开表单或校验时有效不能代替实际生效时刻校验。已成功发布请求的重复到达不重置发布时间，也不能因重试时已过截止反向抹除成功事实；具体幂等结果与事务设计后续明确。

依据 FR-PROMO-030，专题无统一计划时长上限，计划时长为 E - S，不借晚发布改成剩余时长；不能套 30 天或未选的 90 天上限。无统一上限仍须明确有限起止、有效日期类型和上述发布校验，发布后时间固定，不提供自动续期。该选择不改变独立农户助农信息的最长 30 天与结束后 7 天规则；后续请求响应字段、精度、错误码与路由仍未定稿。

### 专题报名条件、有效时间和商品展示

依据 FR-PROMO-001、FR-PROMO-013，管理员可分别设置专题的商品产地限制和商品分类限制，也可分别选择不限。两项都不限时不附加这两类筛选；只设置一项时只检验该项；两项都有设置时必须同时满足，不能按满足任一项放行。服务端依据报名商品的实际产地和分类判断，不用农户经营地区或主营品类代替，也不信任客户端伪造的商品资料或“已符合条件”标记。

上述限制之外，仍需核验实际经营权限、商品属于报名农户且正常上架、专题当前有效发布及管理限制、允许报名的时间范围，并防止同一商品在同一专题重复加入。免人工审核只表示有效报名校验通过后自动加入并展示，校验失败直接说明原因，不创建待人工审核的报名。地区和分类单选含下级已由 FR-PROMO-031、FR-PROMO-032 确认；商品改产地／分类后的进行中参与按 FR-PROMO-033 暂隐藏保留。专题报名条件发布后按 FR-PROMO-023 固定。

FR-PROMO-031、FR-PROMO-032 要求草稿配置分别表达“不限”或一个有效地区／分类节点，不能保存多个并列范围；地区节点可为省、市或县区。报名、进行中列表读取及恢复共同匹配所选节点本身或其下级；使用服务端商品节点与有效隶属关系，不依赖名称字符串、农户经营资料或客户端匹配结果。商品只标某上级不能证明属于所选下级，同名异属不能互相匹配；叶节点可匹配自身。两个维度均限制时取同时满足，不限也不省略其他校验；无效标识不能回退成不限。配置单选不预设最终参数名称、数据类型或错误码，字典来源／深度及节点变更影响仍待设计。

依据 FR-PROMO-014，管理员设置专题原计划开始与结束时间，必须满足开始时间早于结束时间。只有专题已有效发布、尚无有效结束结果、未整体隐藏且其余当前条件均有效时，才在“计划开始时刻含起、计划结束时刻不含”的窗口接受报名。开始前不接受报名；到达原截止或提前结束已经生效，即使原计划结束时间尚未来到也停止报名。报名成功即自动加入展示，不采用提前报名方案。时间格式、精度和时区表达在正式契约中明确，后端以实际状态、有效结束事实和当前时间共同校验，不能只相信前端倒计时、旧页面或原计划时间。

报名重复、并发与重试须保证同一专题、同一商品同时最多一个有效参与关系，不形成重复列表项，不刷新专题开始和结束时间；有效报名与失败请求的返回方式后续设计。该约束不禁止保留多次主动退出及合法重报的历史，物理记录形式按 FR-PROMO-018 后续设计。进入时间范围不代表专题必然已有效发布或其他管理限制已解除；到达结束时刻，即使定时状态更新滞后，也不能继续接受新报名。专题不套用独立助农信息最长 30×24 小时或正常结束后 7×24 小时重发规则；专题缺货仍可报名和展示已由 FR-PROMO-019 单独确认，不再作为库存门槛未决项。

依据 FR-PROMO-015，专题详情顶部展示背景说明，下方以参与商品为主要列表，每项包含商品产地和所属农户，可进入该商品详情和对应农户主页；不采用以农户分组为主的组织方式。相关查询需保持商品、产地和所属农户对应正确，目标页面仍校验其当前访问条件。具体卡片价格表现、排序、分页、专题表单的其他字段和样式仍待设计，不因已确定主组织方式就推定展示所有规格价格或增加农户故事列表。

参加、浏览专题或打开关联详情不会自动打折、改变商品价格、预占库存、加入购物车或生成订单。用户实际购买继续进入商品详情选择原规格与数量，按当前价格、实际可售库存、单农户结算及模拟支付规则操作；无采购意向前置流程，也不重新引入独立采购意向模块。专题结束已明确停止新报名，不能因此自动下架商品、关闭已有订单或修改金额及库存。每次单商品报名、多商品和跨专题参与、主动退出后的重报已由 FR-PROMO-016 至 FR-PROMO-018 确定；缺货、农户下架和定向管理移出见 FR-PROMO-019 至 FR-PROMO-021，不再将这些已确认能力整体列为待定。

### 专题多商品参与、主动退出和重新报名

依据 FR-PROMO-016，农户每次选择一个自家商品报名，可以继续为同一专题提交其他合格商品，不设置该农户在该专题的固定商品数量上限。每次提交均重新校验该商品和专题的当前条件，不因已有一个商品通过就跳过后续商品校验。报名对象是商品，不是零售规格；同商品不同规格不能分别作为多条同时有效参与，也不能用更换请求标识绕过防重复。每次一个商品的提交范围不等于该农户在整个专题只能有一个主推商品。

依据 FR-PROMO-017，同一商品可同时参加多个进行中的专题，各专题分别核验自己的条件、时间、有效状态和管理限制。报名新专题不替换、退出或修改原专题参与；某一专题报名失败也不使其他已有效参与失效。各入口共用原商品、规格、价格和可售库存，不为每个专题复制一份库存或自动设置不同优惠，购买与旧订单金额快照仍沿用原交易规则。

依据 FR-PROMO-018，农户可以主动退出自己某商品在所选专题中的参与，后端核验操作者、商品归属和目标参与，退出后该商品不再出现在该专题当前参与商品列表，并保存退出事实、操作者和有效操作时间。操作不下架原商品，不退出该商品的其他专题，不连带退出本专题其他商品，也不改变已有咨询、订单或库存。保存退出历史不等于向公众公开每次操作记录；自然结束后的专题详情及历史商品范围按 FR-PROMO-024 执行。

本人主动退出后，只要目标专题仍在允许报名期间、无有效结束结果且未整体隐藏，商品和农户当前条件均有效且没有其他有效管理限制，可以重新报名，不额外等待，也不套用独立助农信息的 7 天等待。重新报名须重新通过原有条件校验，不能只因以前成功参与就放行；到达计划截止、提前结束已生效、整体隐藏、当前不再合格或仍受其他有效限制时，不能利用重报获得参与资格。合法重报保留此前退出事实，不清除历史或专题原起止时间，也不由此推定排序刷新、重新获得推荐或重置统计。

退出和重新报名的重复请求、并发及重试须保证同一专题同一商品同时最多一个有效参与，不反复改写同次退出的有效时刻。旧退出请求的重试只能针对其原目标操作，不能在商品已合法重新报名后误退出后一次有效参与；不能只按商品和专题的当前记录无差别执行旧退出。后续接口设计需说明如何区分操作目标、重复请求和当前有效参与，以及返回结果和并发处理，不在此先固定请求字段或版本机制。

保留一份参与记录并追加事件，或为重报建立新的参与记录等物理方案尚未确定；共同要求是保存退出历史、保护后一次有效参与并防止同时重复展示，不能把上述业务规则提前等同于某种新增或恢复接口。专题已结束时是否允许补操作退出、农户下架暂隐藏或专题整体隐藏期间的退出权限、账号／经营权限受限时的退出、结束后内容维护、全平台强制下架和账号禁用对参与的联动、排序与推荐刷新及统计口径继续待 Q-CAMPAIGN-001。正常主动退出后的重报不能清除定向移出、整体隐藏或禁用等有效限制；定向移出的解除和之后重报按 FR-PROMO-021 执行。

### 专题缺货展示、主动下架暂隐藏与管理移出

依据 FR-PROMO-019，全部当前可选规格均无可售库存的商品，在正常上架、有效经营权限、专题条件、报名时间及管理限制等其他条件满足时，也可报名或继续展示，并标注“暂时缺货”。只有部分规格无货而其他当前可选规格仍有可售库存时，不误判整个商品全部缺货。用户可按既有登录与归属规则咨询，但报名、展示和留言不形成预订、供货保证或库存占用；购买仍校验具体规格的实际库存，不能用另一个规格的库存替代所选规格。

依据 FR-PROMO-020，农户主动下架商品时，该商品在各进行中专题的当前参与暂时从对应列表隐藏，但保留原参与关系和历史，不视为农户主动退出或管理员移出。暂隐藏的关系仍受同专题同商品有效唯一约束，不能因公开列表中查不到就再报名生成另一份有效参与。下架不暂停或延长专题时间，专题隐藏本身不重复修改已有订单、咨询或库存；农户下架对商品和订单的既有影响继续按 FR-PRODUCT-005 执行。

商品重新正常上架后，按各专题分别检查未整体隐藏、无有效结束结果且仍在进行、该原参与未退出或被移出、当前参与条件满足且无其他有效管理限制，符合时恢复原参与展示，无需农户重新报名，不新建重复参与、不刷新专题起止。缺货本身不阻止恢复，仍按 FR-PROMO-019 标注。自然到期或提前结束已生效、专题整体隐藏、原参与已退出或被移出，或者当前条件不再满足时，重新上架和旧恢复请求均不能恢复进行中参与展示；任务滞后也不能绕过有效阶段。自然或提前结束后的历史入口按 FR-PROMO-024、FR-PROMO-026 判断，恢复历史入口不等于恢复进行中参与，也不把停止当前展示解释为物理删除历史。

依据 FR-PROMO-021，管理员可以移出指定商品在指定专题中的参与，记录移出原因、操作者和有效时刻，使其不再作为该专题当前参与商品展示，并限制农户自行重新报名。此限制作用于该专题和商品的组合，不是全平台强制下架，也不移出其他专题的参与，不下架原商品，不改变既有订单、咨询、金额或库存。农户普通报名、换规格、重新上下架或替换参与记录均不能清除该项有效限制，普通农户也不能执行管理员解除操作。

管理员解除该项移出限制后，记录解除事实、操作者和有效时刻，只解除目标限制并保留此前管理历史，不自动恢复原参与。农户仍须主动重新报名，且实际处理时处于允许报名期间、无有效结束结果、专题未整体隐藏、当前商品与经营条件有效且无其他有效限制，才形成新的有效参与结果；不能因曾经参与或刚解除限制跳过校验。全平台商品下架、账号限制、专题整体隐藏或其他专题的独立移出限制不随这次解除一并清除，不借解除操作延长专题时间或变动交易数据。

暂隐藏、管理移出、解除及重新上架的先后顺序不能使有效限制失效。已经被移出的参与即使先前暂隐藏，后来解除限制并重新上架也不自动恢复，仍须按前述流程主动报名。重复操作与重试应保持有效结果和管理历史，不改写同一次有效操作时间；针对旧一次移出限制的解除请求，不能在后来再次移出形成新限制后误清除后次限制。正式契约需明确操作目标、权限、重复与迟到请求、并发及失败恢复，不在此固定路径、字段、状态枚举或实现方式。

上述商品暂隐藏只处理其专题当前列表项，以及管理员针对商品与专题的定向移出，不据此规定商品旧链接不可用；专题整体隐藏的旧专题链接按 FR-PROMO-027 处理。商品改产地／分类的进行中参与按 FR-PROMO-033；全平台限制联动、隐藏期间其他操作、结束后管理及新增不匹配情形的历史影响、排序和统计等继续在 Q-CAMPAIGN-001 跟踪，按模块设计时处理。恢复与重报仍校验当前条件及有效结束事实，独立助农信息继续使用自身规则。

### 商品产地或分类修改后的进行中参与

依据 FR-PROMO-033，商品资料经原权限校验成功修改后，逐个检查已有进行中专题的当前条件。不再匹配的关系保留并退出该专题当前公开商品列表，不自动退出或移除，不新建人工审核；仍匹配的其他专题不因这次资格联动受到影响，也不影响商品本身、已有订单、咨询、价格和库存。

后来调整为符合条件，专题尚未自然或提前结束、原参与未退出或移出且其他条件有效时恢复原展示，无需再次报名。无需改回最初的具体节点，只要当前商品符合该专题即可。恢复须同时检查商品正常上架、经营权限、专题整体可见性及其他限制；全部规格缺货按原规则标注，不单独阻止恢复。仍整体隐藏时不公开，原时间不暂停、不补时。

暂隐藏仍占同专题同商品有效参与唯一关系，不能重复报名产生副本。因不匹配隐藏后若又被管理员移出，后来解限并改为符合也仍须按 FR-PROMO-021 主动重报，不能通过资料修改或旧恢复请求清除移出事实。公开读取在资料修改实际生效后检查当前条件，缓存与延迟任务不能继续返回不合格的进行中列表项；并发报名、改资料、退出、移出或结束要核对实际生效状态，具体幂等及响应策略后续设计。

本条只定义进行中展示联动，不增加新的商品详情访问限制、咨询权限或隐藏期间退出权限，也不把暂隐藏提示当作新增通知模块。结束后不能恢复进行中；新不匹配情形的历史归属、结束后商品修改及历史字段取值仍待 Q-CAMPAIGN-001，不按主动下架的历史规则自动补全。

### 专题结束后的详情与历史商品入口

依据 FR-PROMO-024、FR-PROMO-026，专题自然到期或管理员有效提前结束后退出进行中列表并停止报名，旧链接在当前访问权限允许时保留详情与背景，分别明确显示自然结束或“已提前结束”。历史截止时点依结束来源确定：自然到期使用原计划结束时刻，提前结束使用服务端首次有效提前结束时刻，不能混用。两种结束均不重新开放报名、不下架原商品、不改动已有订单、咨询、金额与库存；历史入口进入当前商品或农户页面后按现行权限与交易规则处理。专题整体隐藏或受其他有效访问限制时，旧链接不能绕过限制公开历史详情。

历史商品范围按对应有效结束时点保留的参与判断，即该时点未退出且未被管理员移出的参与；仅因农户主动下架而暂隐藏、但参与关系仍保留的商品也在此范围内。不能把结束时公开列表实际可见的商品直接当成全部历史成员，也不能把所有曾经报名过的商品一并纳入。此前退出或被移出后，在对应截止前已经合法重报形成有效参与的，依据结束时最新有效参与判断；整体隐藏期间自然到期，也不能因公开列表为空而清空保留的参与范围。

上述历史规则覆盖既有已确认情形；FR-PROMO-033 新增的产地／分类不匹配隐藏是否计入结束历史、历史展示是否继续匹配及结束后改资料的影响仍待确认，不直接套用仅主动下架的结论，不预先在接口中承诺纳入或排除。

是否属于结束时的历史范围，与当前能否显示商品或农户入口分开校验。属于该范围的商品，当前不允许公开时不放行相应入口；后来恢复公开资格，可以恢复历史页入口，但不恢复进行中参与、不重开专题或延长时间。结束时已经退出或被移除且没有有效重新参与的商品，之后仅凭上架、补货或解除限制不能补进历史范围；历史集合不随当前商品状态任意增删。

结束识别和成员范围须依据结束来源、对应有效截止及参与历史，而不是到期任务执行或用户首次打开历史页的时间。已经有效提前结束的，之后原计划到期任务不能覆盖结束来源、实际结束时间或历史成员；延迟任务、重试和缓存不能把截止后报名当成截止前参与，也不能用旧退出请求影响截止前合法重报的结果。接口设计需说明如何返回一致的结束标识、历史成员和当前入口；商品资料快照或当前值、时间精度及实现形式仍待设计，不预设历史字段结构。

自然及提前结束的历史均受专题整体隐藏和当前访问权限约束。结束后说明修改、其他管理动作、原商品和农户访问限制的剩余细节仍待 Q-CAMPAIGN-001 及对应模块确认，不能将保留历史解释为所有旧内容永久公开或允许补报名。

### 管理员提前结束、专题整体隐藏与解除

依据 FR-PROMO-026，有权限的管理员可对仍在进行的专题记录原因并主动提前结束。后端核验当前阶段与操作权限，成功后立即停止报名和进行中展示，保留原计划起止时间，另保存首次有效实际结束时刻、结束来源、操作者和原因，明确标记已提前结束。实际结束不能通过改写原计划截止代替；该结束不可恢复为进行中，即使当前仍早于原计划截止也不能继续报名或由编辑、上架恢复、解除隐藏重新开启。

提前结束、报名和自然到期发生交错时，以服务端有效状态和实际生效先后校验。已经自然到期的不能补记成一次新的提前结束；已有有效提前结束的重复请求不刷新首次结果，后来的原自然到期任务也不覆盖其结束事实及历史成员。提前结束后的历史按 FR-PROMO-024 的成员与入口规则处理，但截止换成首次有效实际结束时点。具体事务、幂等和响应形式后续设计，不因管理操作增加报名预审。

依据 FR-PROMO-027，管理员可临时整体隐藏已发布专题，范围包括预告、进行中、自然结束及提前结束的专题。隐藏后退出公开列表，普通访问旧链接仅显示暂不可用，后端不返回原介绍或商品列表内容，并阻止新报名或重报；不能只靠前端遮挡内容。草稿仍沿用草稿规则，不因本功能取得公开资格；农户和普通用户不能执行管理隐藏或解除。

整体隐藏保留专题、参与及管理历史，不等于提前结束，也不修改已有效的自然或提前结束事实。原计划时钟照常推进，到达开始或自然截止均不自动解除隐藏，不补偿隐藏时长；隐藏期间自然到期仍按原计划截止确定结束及历史成员。隐藏、解除及阶段推进不改动商品、其他专题、已有订单、咨询、金额或库存。

管理员手动解除整体隐藏后，先检查已经存在的有效结束结果，再结合原计划时间与其他访问限制决定展示：尚未开始且可公开时恢复预告；无有效结束结果且仍在进行时，恢复允许公开的合格原参与，并按其余条件允许新报名；已经自然或提前结束时只恢复允许访问的历史详情，不恢复报名。不能因为提前结束专题的原计划截止尚未来到，就将其当成仍在进行。

解除整体隐藏只解除该专题这一项公开限制，不清除商品下架、账号限制、专题内定向移出等其他限制，也不批量恢复已退出或已移出的参与。报名与参与恢复须统一检查有效结束事实、整体可见性、参与状态和当前资格；重复管理请求、旧恢复任务或延迟自然到期处理不能清除其他限制、重置计划时间或改变首次有效结束结果。

整体隐藏期间是否允许说明编辑、农户退出或管理员提前结束、未开始专题的取消、隐藏／解除的理由字段和记录可见范围、结束后其他管理操作、全平台商品或账号禁用的详细联动仍待 Q-CAMPAIGN-001、Q-ADMIN-001。不能从整体隐藏的管理权限直接推定这些剩余动作均可执行，也不能把单个商品下架暂隐藏与整个专题公开限制当成同一操作。

### 主动助农信息与内容发布边界

依据 FR-PROMO-002、FR-PROMO-010，具有有效经营权限的农户可关联自己正常上架的已有商品发布助农信息，表达推广诉求，资料校验通过后在助农页公开展示，不再等待逐条人工审核，也不要求先有咨询或成交记录。接口须检查商品存在、商品及发布者归属、当前上架状态和实际操作权限，不能只信任请求中的农户 ID 或旧表单；用户可由符合当前公开和入口条件的信息了解产品，再按既有权限规则咨询或进入商品选购。

助农信息属于农户主动推广，不另建商品业务。发布或浏览信息不自动创建商品、留言或订单，不预占库存；价格、规格和库存沿用原商品业务，不提供独立覆盖成交价或库存的入口。真正购买仍须经过既有商品可购买状态、结算、金额和库存校验，不能借推广入口绕过下架或管理限制。公开发布不自动加入任何专题，也不自动获得首页推荐；专题报名继续按 FR-PROMO-001 单独校验。

公开展示不代表平台完成困难认定、产地资质认证或增收保证。关联商品、表单、期限、四项编辑、主动结束、正常结束后重发、发布资格、缺货展示、农户主动下架联动及正常结束历史入口已有下述规则；独立改期／延期、管理员强制下架或经营权限变化的联动、管理员管理范围及下述交叉边界仍待 Q-PROMO-001，不能提前补齐这些操作。

### 助农发布表单、单商品关联与截止时间

依据 FR-PROMO-004、FR-PROMO-005、FR-PROMO-006，发布输入及复用资料的范围如下。这里是业务含义，不是最终 DTO 字段名、类型或传参格式。

| 内容 | 必填性或来源 | 接口约束 |
| --- | --- | --- |
| 关联商品 | 必填 | 恰好一个自家正常上架的已有商品，后端核验存在、归属及当前权限；不能不关联、关联下架商品或一次提交多个商品，零库存本身不阻止发布 |
| 标题、推广说明 | 必填 | 用于本条推广表达，缺失或空内容不能形成有效发布；长度及具体文字校验后续设计 |
| 推广截止时间 | 必填、自选 | 按 FR-PROMO-006 校验，必须晚于首次有效发布且不超过该时刻起 30×24 小时 |
| 供货时间 | 选填 | 未填写也可发布，不表示随时、全年或立即供应；填写后仍须按后续明确的格式校验 |
| 希望对接的买家类型 | 选填 | 不填不阻止发布，填写后按已设计范围校验；枚举及单选／多选形式仍待确定 |
| 图片、产地、价格和库存 | 复用关联商品 | 不要求再次上传助农图片或另填一套产地、成交价格、库存，不通过本表单改写原商品交易数据 |

不能暗增推广类型、困难证明、资质附件或额外图片必填项。图片等资料采用实时读取还是保留快照、商品资料修改后的展示联动仍需设计，不能把“复用”直接理解为完整快照方案已经确定。供货时间描述何时供货，推广截止时间描述本条信息何时结束，两者不自动相等，也不能因供货时间选填而省略必填的推广截止。

每条助农信息只关联一个商品，该商品仍可包含原有多个规格，不要求把多规格拆成多条助农信息或只保留一个规格。关联数按商品而非规格计算，实际购买仍进入原商品选规格流程。发布后关联商品固定，不允许通过编辑换绑；FR-PROMO-009 限制同一商品同时最多一条正在推广，正常结束后按 7×24 小时间隔判断新建资格，不是该商品终身只能发布一次。

首次有效发布时间由服务端在首次有效发布时确定；有效范围为：首次有效发布时间 < 自选截止时间 ≤ 首次有效发布时间 + 30×24 小时。不能用客户端提交的发布时间、打开表单时间或失败尝试作为可伪造的计时起点，截止已过、等于起点或超过上限时不能有效发布。具体时间输入格式、精度与展示约定在后续契约中明确，不以自然月或未经确认的日期换算替代该时长。

原记录的普通编辑不重置首次有效发布时间或原截止时间，不自动续期；四项编辑和主动提前结束分别按 FR-PROMO-007、FR-PROMO-008 执行。达到截止时刻后，本条信息退出正在推广列表并自然结束，保留记录，正常结束历史的公开和入口规则见 FR-PROMO-012；不下架原商品、不取消已发生的咨询或订单，也不改变原交易库存。

正在推广列表必须按服务端实际有效时间和业务状态判断，不能仅凭尚未更新的缓存或任务状态继续展示到期信息。到期任务、旧请求或重试不能重新激活原记录、重置时间或重复改变关联业务；调度、缓存失效和重试实现后续设计。正常结束历史不再从原条新增咨询，不能仅隐藏前端按钮而继续接受旧入口提交。

### 推广信息编辑、主动结束与重发

依据 FR-PROMO-007，只有本人仍在推广且当前权限有效的信息可修改标题、推广说明、供货时间和希望对接的买家类型，资料校验后直接生效，不进入人工审核。标题和说明仍须有效，两个选填项可以清空；关联商品、首次有效发布时间和原截止时间不能修改或夹带覆盖，商品价格库存继续由原商品模块维护。编辑时后端重新校验归属、有效状态和实际时间，已经自然到期或主动结束的记录不能再编辑；与结束并发时，旧编辑不能覆盖已生效的结束结果或恢复推广。

依据 FR-PROMO-008，本人可以主动提前结束仍在推广的信息。成功后退出正在推广列表、保留原内容、商品关联、首次有效发布时间和原截止时间，另记录有效结束原因及时间；该动作不是删除，也不通过改写原截止模拟提前结束。农户不能自行恢复该原记录，商品及已有咨询和订单沿用原业务状态，不因结束推广被取消或改变库存。

尚未形成有效结束结果的记录，后端有效处理时已经达到或超过原截止的，按自然到期处理，不能再记成手动提前结束以重设计时。成功手动结束后，重复结束请求或原到期任务不能覆盖最初的有效结束原因和时间。结束原因表达业务上的自然到期或主动结束，具体字段和是否需要额外填写说明后续设计，不据此擅增农户必填原因表单。

依据 FR-PROMO-009，同一商品同时最多有一条正在推广的信息，按商品而非规格判定；改变规格、标题或请求标识不能绕过。重新发布必须同时满足当前归属和发布资格、没有该商品正在推广的信息，以及按最近一次有效正常结束计算的 7×24 小时间隔；不能选取更早历史记录计算，也不能将管理员限制、商品下架或经营权限变化直接等同正常结束而放开重发。

| 最近一次有效正常结束方式 | 重发间隔起点 | 时间边界 |
| --- | --- | --- |
| 自然到期 | 该原记录的原截止时间 | 到期任务晚执行、页面晚访问或重试均不推迟起点；未满 7×24 小时不能重发，恰好满且其他条件有效时允许 |
| 本人主动提前结束 | 服务端首次成功执行该主动结束的时间 | 重复点击、网络重试和之后的原到期任务不刷新起点；未满 7×24 小时不能重发，恰好满且其他条件有效时允许 |

符合条件后，由农户主动提交新记录，仍需选择晚于其自身首次有效发布且不超过该时刻起 30×24 小时的截止；不自动重发或复活旧记录。旧记录内容、时间及原咨询的数据关联保留，不迁移到新记录充作新推广反馈。并发创建须保证同商品最多一条正在推广，失败与重试不能刷新结束时间或等待期；具体事务、唯一性及返回协议后续设计，不能仅靠前端按钮防重复。独立延期／改期及管理限制的具体联动仍待确认，普通编辑固定截止、正常结束重发也不能绕过这些限制。

### 发布资格、缺货展示、主动下架及历史入口

依据 FR-PROMO-010，首次发布和正常结束后的合法新建均须关联本人正常上架的商品，经营权限有效，并满足原有期限和同商品名额等条件。上架状态与库存数量分开校验：商品全部当前可选规格的可售库存均为零时，仍可发布或继续展示推广，并标注“暂时缺货”；不能因一个规格无货，就把仍有其他可选规格有货的整个商品判为全部缺货。具体规格的库存由原商品业务维护，实际下单仍校验选中规格的真实可售数量。

缺货推广仍允许按原登录及归属规则咨询，但不保证之后一定供货，也不形成预订、付款或库存占用。不能把填写供货时间、发布推广或发送留言当成已有库存、已承诺交货或零库存也可下单；缺货标识及购买校验不能仅相信客户端传值。

依据 FR-PROMO-011，农户主动下架商品时，其对应尚未结束的推广退出公开列表，旧链接只展示暂不可用，不允许从该条新增咨询；服务端读取及提交入口都需校验当前有效条件，不能通过缓存内容、旧页面或直接请求绕过。保留原推广及既有咨询和订单，既有业务继续按各自规则处理；商品下架自身对订单的影响仍按 FR-PRODUCT-005，不另由推广隐藏重复操作订单或库存。

暂隐藏不等于推广结束或暂停计时：首次有效发布时间、原截止和内容保留，仍占同商品的一条推广名额，不能因退出列表就另发一条。商品合规重新上架、符合当前展示条件且原条尚未结束时恢复展示；恢复的是同一条记录，不是重发，不重设计时。仍正常上架但全部规格零库存的，沿用 FR-PROMO-010 的缺货展示，不额外要求有库存才恢复。已经自然到期或主动结束的原条不能因商品重新上架而恢复推广；重复上下架或旧恢复请求也不能覆盖结束结果。

隐藏期间达到原截止仍按原截止自然结束，重发等待期从该原截止起算 7×24 小时，不从下架、重新上架或任务执行时间起算。未结束时的恢复展示与到期竞争，需以服务端实际有效时间及结束事实决定，不能只靠旧的暂隐藏标记恢复到期记录。商品仍下架时，到期后是否立即公开历史内容或继续暂不可用、已结束历史关联商品后来主动下架时的详情优先级，以及隐藏期间编辑／主动结束的入口权限仍待 Q-PROMO-001，本轮不预设这些交叉结果。

依据 FR-PROMO-012，在未叠加上述未决限制的正常场景中，自然到期或农户主动结束后的原内容保留公开历史详情，明确标注“已结束”，不进入正在推广列表，也不允许从旧条新增咨询。既有咨询及其数据归属保留，不因结束或公开历史而删除、迁移或对外公开参与者私有资料；农户不能借历史详情编辑或恢复已结束原条。用户可跳转当前允许公开的商品或农户继续了解、对接，跳转后的沟通和购买仍校验目标对象的当前权限，不借旧链接放行受限内容或旧条的新提交。

历史原助农内容的保留不等于已经决定复用商品图片、产地、价格、库存采用快照还是实时展示；该资料变化联动仍待设计。管理员强制下架、账号或经营身份禁用及权限解除对推广展示、历史访问和恢复的具体影响仍待确认，不从农户主动下架的恢复规则推定管理员限制可自动解除。

### 农户故事与产地介绍维护

依据 FR-CONTENT-001，农户维护自己的图文故事和种植介绍，管理员维护产地介绍，分别按归属、角色及资料校验发布，无投稿审核流程。农户不能修改其他农户的故事，也不能借故事入口维护管理员负责的产地介绍。故事用于解释“谁在种、怎样种、产品有什么特点”，不因内容发布而修改商品价格、库存或生成交易；新增内容能力不增加入驻时必交故事、证明附件或第二次审核。管理员对农户内容的干预权限、故事篇数、字段、图片处理、是否独立页面及撤下规则仍待 Q-CONTENT-001；不预设单篇／多篇、文章社区、评论体系或管理员统一代写农户故事。

### 推广反馈接口的范围与统计口径

依据 FR-PROMO-003，农户可查看自身推广反馈，管理员可查看平台汇总，首版覆盖浏览和咨询两个方向。查询必须按真实登录身份限定农户数据范围，不能替换农户 ID 就读取他人反馈；管理员汇总能力也不自动赋予公开访客名单、咨询者身份或其他私有业务资料的权限。留言详细读取仍按参与者归属规则处理。

反馈用于说明获得了多少关注和需求，不能把浏览或咨询直接标为真实成交、真实助农收入或增收；模拟交易继续保留演示属性。读取统计不创建采购需求、不改变原咨询或订单状态。不能因为用户曾访问某专题就把其全部咨询或订单归因于该专题，不自动新增收益排行榜或对外公开的个人数据。

浏览按次数还是人数、咨询按消息还是会话、时间区间及边界、去重方式、专题／助农信息／普通商品入口的来源归属、空态和统计延迟均待 Q-PROMO-001。正式契约需在这些口径明确后解释指标定义、单位、范围、更新时点和权限，再确定参数、字段与数值示例；当前只确认能力方向，不虚构精确统计结果或最终接口格式。

### 普通购买与批量询问的首版边界

依据 FR-COMM-002，普通购买从专题或有效助农信息进入商品详情，按规格、数量和既有结算规则下单，不要求先留言或提交另一份采购表单。特殊批量需求沿用 FR-COMM-001 的站内文字留言，用户提出问题，农户稍后回复即可，不要求双方同时在线；异步留言仍按登录、参与者归属、未读及当前来源入口限制设计，不借批量询问放开隐藏或已结束推广的新咨询入口。

发送、读取或回复留言不自动生成订单、付款、预订或库存占用，也不增加承接、成交、完结等业务状态。买家若随后按平台商品规格购买，仍由其通过原下单流程主动操作，留言内容不自动转成订单或覆盖价格、数量与库存。首版不强制为留言填写联系人称呼或手机号，不因采用站内留言就增加短信校验、短信通知或实时在线聊天要求。

按 D-062 的范围调整，FR-INTENT-001 保留为后续扩展，**不属于首版交付**。当前不设计独立采购意向表单、列表、跟进状态、转单能力、专用接口或意向统计；以后启用时重新确认范围和契约，不能把此前讨论中的字段选项当成已生效需求。当前没有已经实现的独立意向接口或数据需要迁移、兼容或清理，本次仅同步设计范围。

## 4 交易接口的重点约束

1. 创建订单时，后端读取真实商品与规格、所属农户、可售库存及运费，核算金额；客户端提交的价格不能作为可信依据。后端成功创建订单时保存金额快照，此后商品价格与固定运费修改只影响新订单，不能覆盖旧订单金额。
2. 一笔订单只属于一家农户。多规格创建订单与库存预占保持一致，失败时不能留下其他规格的无主占用。
3. 模拟支付不能再次扣减已经预占的数量；未支付取消、30 分钟超时、管理员强制下架关闭及批准的发货前退款不能重复返还。农户主动下架本身不返还旧订单的预占。
4. 支付与超时关闭、支付与管理员强制下架关闭、退款申请与发货等竞争需写明允许前提及结果。支付与关闭只能有一个有效结果，不能既支付成功又按未付款订单释放库存。已经成功提交的农户待审核退款会阻止发货，不能仅靠隐藏前端按钮实现。
5. 农户拒绝后的 24 小时复核窗口内及管理员待处理时暂停发货；截止前已经申请复核的流程，不再按旧窗口到期恢复发货。过期申请由后端拒绝。
6. 农户待审核或管理员待处理时允许用户有效撤回；撤回恢复发货、保留记录，但不取消已付款订单、退款或返还库存。并发审核和重复请求不能覆盖已经生效的结果。
7. 超过 48 小时未处理只触发超时待办，管理员可以接手农户超时申请。接手后原农户不能继续有效审核，管理员不必伪造一条农户拒绝记录才能处理。
8. 恢复发货权限不等于自动发货；窗口到期、撤回、提醒或接手均不直接退款或释放库存。材料、通知和结束后的重新申请限制仍待 Q-REFUND-001。
9. 错误响应需让前端判断是刷新订单状态、修正输入还是重试；最终错误码与重试协议另行设计。

FR-ORDER-003 的金额快照至少解释订单明细的成交单价、数量、行金额、商品合计、固定运费和订单总额，模拟支付成功后保存原模拟实付金额。待付款订单在原有 30 分钟期限内按已创建订单的金额支付，整单退款按原模拟实付退回，不能在支付或退款时重新套用当前商品价格或运费。

加入购物车或打开确认订单页不构成锁价；确认页展示后、提交前发生价格变化时如何提示并让用户重新确认，仍待 Q-ORDER-001。锁价不延长待付款期限，农户主动下架后的原有效未付款订单仍可按原金额、原期限支付；管理员强制下架则关闭包含该商品的未付款整单，关闭后不能支付。农户禁用、规格移除或停用后的旧订单操作仍待 Q-FARM-001、Q-PRODUCT-001，不能由锁价自动推定。订单收货信息按 FR-ORDER-004 保存；商品／规格名称、图片等其他快照范围仍另行设计，不由金额或地址规则自动确定全部字段。

### 订单收货信息与买家备注

依据 FR-ORDER-004，创建订单时校验并保存收件人、联系手机号、地区、详细地址四项收货信息，作为这笔订单自己的快照。接口需说明如何传入及返回这些内容；输入来源是地址簿时需校验记录属于当前用户，不能借他人的地址 ID 读取资料，也不能仅保存地址簿记录 ID、每次查询时再读取当前地址内容。地址簿之后的修改或删除不能自动改变旧单收货信息，也不能使旧单地址缺失。

仅该订单买家可在订单仍有效、未付款且未过原 30 分钟期限时，主动修改这笔订单的收货信息。后端需在执行时检查所属用户、实际订单状态、时效及有效的管理限制，不能凭客户端显示“待付款”放行已经取消、到期或受强制下架关闭影响的旧请求。修改成功只改变目标订单的地址快照，不修改其他使用同一地址的订单，也不改动规格、数量、金额、库存占用或原付款截止时间。校验失败不能部分覆盖四项资料。

修改与支付并发时，地址修改先有效完成，支付采用已修改的订单地址并将其固定；付款先有效完成，旧修改请求不能再覆盖地址。取消、过期或管理员强制下架关闭先使订单失效时，后续地址修改也不得生效或恢复订单。已付款订单的收货信息固定，未发货、退款待处理或之后撤回退款都不赋予改地址权限。具体字段长度、地区编码及校验格式在契约设计时确定，地址簿的具体管理能力另行确认。

依据 FR-ORDER-005，订单可带一条选填的普通文字买家备注，在创建订单时保存，未填写也可正常购买；这是一条整单备注，不是每个明细单独一条。创建后固定，不通过订单地址修改、付款或其他更新入口覆盖。所属农户可在处理该订单时查看备注；接口仍需校验订单归属和读取权限。备注用于表达买家意愿，不自动修改收货地址、规格、数量、成交价格或运费，也不自动成为农户或平台已经承诺提供的服务；保存和展示为普通文字，不作为脚本或系统指令执行。长度、空白处理及展示格式在后续契约中说明，不自定未确认上限。

### 模拟发货与收货节点

依据 FR-SHIP-002，订单所属农户为允许发货的订单选择模拟承运方，后端在确认发货有效完成时生成演示单号，保存发货时间并更新对应订单状态。客户端不通过手填单号替代已确认的系统生成方式；承运方选项、单号格式及返回字段仍在正式契约中设计。

发货必须校验订单已模拟支付、尚未有效发货且不处于退款暂停发货阶段。农户待审核、拒绝后的有效 24 小时复核窗口、管理员待处理及超时仍待处理的限制继续有效。发货与退款申请竞争时，按先有效完成的业务结果处理，不能两边都以旧“已付款未发货”状态成功。重复点击、重试或并发发货最多形成一次有效发货结果，不重复生成记录或更换已生效的演示单号；失败不能留下看似有效的单号和发货节点。模拟发货与确认收货不再次扣减或返还原订单占用，不修改原金额、付款后固定的收货信息或买家备注。

演示物流展示已发货及有效确认收货两个节点和各自时间；确认收货节点可来自购买用户手动确认或 FR-ORDER-006 规定的系统到期自动确认，需明确区分来源。页面和接口说明保留模拟／演示标识，不调用真实物流查询，不编造揽收、运输、派送或真实承运签收记录。生成演示单号或打开详情不会直接完成订单。发货信息纠正和分批发货仍待 Q-ORDER-001，不由这两个节点的设计自行补出默认流程。

### 手动与到期自动确认收货

依据 FR-ORDER-006，保留购买用户手动确认本人待收货订单的能力；从有效模拟发货时间起满 7×24 小时，订单仍处于待收货时，由系统自动确认并正常完成。计时不从下单、付款或页面访问开始，不按自然日零点凑足 7 天，也不因请求重试重新计算有效发货时间。接口与任务设计应说明服务端如何核验发货时间、截止时间和当前状态，任务扫描周期、失败重试与重启补扫在后续技术设计中落实。

订单详情需表达实际确认时间和确认来源。系统自动完成应明确显示“系统自动确认收货”，不能伪装成买家点击，也不能视为真实物流公司签收；客户端不能通过提交“系统确认”来源或伪造发货时间提前完成订单。普通用户确认接口仍仅允许订单购买人调用，内部自动处理的权限和入口单独设计，不因此开放代他人确认权限。

手动确认与自动任务并发、重复请求或任务重试最多产生一次有效完成结果。已经完成、取消、退款关闭或其他不符合待收货条件的订单不能被重写，先有效完成的时间与来源不能被后到请求覆盖。两种确认方式均保留原金额、库存效果、已付款地址及固定备注，不再次扣减或返还库存；订单完成只产生评价资格，不自动生成评价、星级或好评。

### 整笔订单一条购买评价

依据 FR-REVIEW-001、FR-REVIEW-008，购买人可在订单通过手动或系统自动确认正常收货完成后、实际完成起 30×24 小时内，自愿为这一整笔订单首次提交评价。接口围绕目标订单、购买用户及期限校验资格；一笔订单包含多少商品、规格或购买份数，都最多有一条有效评价。取消、未付款关闭和退款关闭不能当作正常完成，同一用户对不同已完成订单分别拥有各自期限内的评价资格，即使购买的是相同商品也不合并为一次终身评价机会。

提交时必须由用户明确选择 1～5 星级，未提供星级不能由前端或后端默认补成五星；文字和图片均选填，最多 3 张图片，只选择有效星级也可以提交。星级步长尚未确定，当前不能据“1～5”自行限定只能选择整数或默认允许半星；字段类型及精度、文字长度、图片格式和大小均在后续契约中明确，不暗增最低字数或必传图片要求。依据 FR-REVIEW-002，参数校验失败不能产生有效评价，不能只保存评分却悄悄丢弃超出上限的图片后当作全部提交成功。

评价文字按普通文字处理。图片上传成功不代表评价已经提交，评价创建时需校验图片使用权限及本条评价关联的图片总数，不能引用他人的私有上传内容，也不能靠分批上传绕过最多 3 张的限制；上传接口、引用形式及未使用文件处理另行设计。

创建接口需说明重复点击、网络重试和并发提交如何保证同一订单最多一条有效评价；重试响应与状态冲突错误码另行设计。依据 FR-REVIEW-003，评价一经有效提交，星级、文字及关联图片均固定，不提供买家改评入口，后端也不能通过再次创建、通用更新或替换图片关联覆盖已有内容。不设计改评次数或内容版本切换流程；FR-REVIEW-007 已确认不提供买家／农户自行删除或追加，管理员只隐藏／恢复而保留记录，不能据可见性变化重新开放评价或回复资格。

### 首次评价期限与重试

依据 FR-REVIEW-008，首次评价截止时间为订单的实际有效收货完成时间加 30×24 小时。服务端判定首次有效提交时必须尚未达到截止时间；到达截止时刻及之后均不能首次提交。手动确认使用手动实际完成时间，系统自动确认使用任务实际有效完成时间，不能以计划自动确认时间、有效发货时间、页面倒计时或客户端传入时间替代。面向购买人的响应需能说明当前评价资格和截止时间，页面展示不替代首次创建时的再次校验。

首次校验失败且未形成有效评价不会消耗资格，但修正后重试仍要重新校验期限；截止前打开评价页、上传图片或发送过失败请求都不保留过期后的提交机会。已有成功记录的重试则需识别原结果，不能在截止后生成新评价、覆盖内容或把原评价变回未评价；重试具体返回形式仍在契约中设计。

30×24 小时只限制买家首次成功提交，不是已发表评价的展示期限，也不限制管理员隐藏或恢复。已发表内容不会仅因期限届满自动下架，未评价订单也不自动生成好评。农户对已有评价的一次固定回复不另设时间期限，仍须满足归属、尚未回复及其他有效权限；对已隐藏评价是否可首次回复仍待 Q-REVIEW-001，不能从“不限回复期限”推定放开该场景。

### 农户一条固定回复

依据 FR-REVIEW-004，已有评价所属订单的农户可为该条评价发布最多一条普通文字回复。接口需以持久化的评价、订单和农户归属核验操作者及目标，不能只信任客户端传入的农户 ID；没有评价时不能先创建回复，其他农户或买家不能代替该农户发布。回复与原评价关联展示，不作为另一条购买评价，也不更改买家星级、文字、图片或订单交易资料。

回复发布后内容固定，不提供编辑或多轮对话。重复点击、网络重试与并发提交最多生成一条有效回复，带不同文字的再次提交不能覆盖第一次已生效的内容；具体重试响应另行设计。回复须有有效普通文字，空白不能形成有效回复，不提供回复图片或星级，不作为富文本或系统指令执行；长度及空白处理细节仍待设计。首次评价或回复校验失败且没有形成有效记录时，不占用该次提交资格，修正后仍按当前权限与适用期限重新校验；农户回复不另设期限，不等于忽略尚未明确的隐藏评价回复边界。本规则不新增逐条人工审核前置流程，内容校验和所属权限仍必须执行。

### 农户主页公开展示与私有订单访问

依据 FR-REVIEW-005，整单购买评价公开集中展示在对应农户主页，农户回复关联其原评价展示。商品详情只提供指向该商品所属农户的“查看农户评价”入口，不直接列出本商品相关订单的评价，不复制评论为商品评价，也不把整单星级分别计入各商品评分。接口设计需说明公开列表如何按评价订单所属农户取数，以及商品入口如何定位正确农户，不能把同一订单的多条商品明细展开成重复评价。

公开响应与订单私有响应需分别定义返回内容及权限，引用同一份有效评价和回复业务记录，不能维护互相矛盾的公开与私有副本。公开评价不意味着公开原订单详情、订单号、收件人、联系手机号或收货地址；不能因为内部评价关联订单就直接返回完整订单实体，或允许通过评价标识越权读取原订单。对于正常可见内容，买家在自己的订单、农户在所属销售订单中依原有归属权限查看评价及处理回复，和农户主页的公开展示位置不冲突；隐藏内容在私有页面具体怎样呈现仍待确认。公开查询不能扩大私有操作权限。展示需区分买家评价与农户回复，回复不作为第二条评分，也不表示平台裁定或退款结论。

依据 FR-REVIEW-006，公开评价的买家身份统一为“匿名用户”和默认头像，不提供逐条选择实名或匿名的开关。匿名响应应由服务端直接生成，不能先返回买家真实昵称、真实头像或整包内部买家资料再交由前端遮盖，也不附带可直接访问购买人资料的账号标识或个人主页入口；游客与其他登录用户使用相同公开规则，更改账号昵称头像也不改变匿名展示。内部评价仍关联原购买用户、订单和农户，用于原有鉴权及管理，不因匿名取消数据归属。农户回复仍明确标为农户身份，不将回复作者替换成“匿名用户”。匿名是公开身份规则，不自动承诺替用户填写的文字或图片进行内容脱敏。

### 管理员隐藏与恢复评价或回复

依据 FR-REVIEW-007，仅有相应管理权限的管理员可对评价或农户回复执行隐藏、恢复，每次须提供有效处理原因并记录重要操作信息；买家和农户不自行删除、隐藏或恢复评价／回复，也不追加评价。管理接口需区分操作对象和动作，保存操作者、对象、时间、原因与结果，只改变可见性，保留原内容、关联及记录，不能改星级或文字，也不能把隐藏实现为物理删除。公开读取按最新有效状态处理，旧页面、直接请求和缓存不能绕过隐藏；具体失效及返回策略在设计时落实，不声称能收回浏览者此前已经看到或保存的内容。低分本身不自动判作违规，不按星级自动隐藏，不新增逐条人工预审。

评价自身可见性与回复自身可见性需分别表达，公开读取同时校验父评价及回复：父评价隐藏时，其回复不得独立公开；父评价恢复时，未被单独隐藏的回复可随其展示，曾被单独隐藏的回复仍保持隐藏。只恢复回复但父评价仍隐藏时，回复仍不能公开。管理操作不能清除另一对象自己的隐藏状态，也不能因重复操作、并发或重试重置每单一次评价和每条一次回复的限制；具体并发与重试响应在接口设计中说明。

隐藏内容在买家／农户私有页面的展示、能否对隐藏评价首次回复、处理原因向谁展示、管理处置标准、记录保留期限、列表排序和平均分统计等仍待 Q-REVIEW-001。星级步长、文字长度、图片格式大小及管理原因等具体字段参数继续待设计，不再将统一匿名、仅管理员隐藏恢复或首次评价期限列为未决。

### 库存增减与下架操作的契约边界

依据 FR-INV-002，已有规格的库存维护表达为本次增加或减少多少份，不能接收客户端计算出的最终可售量并直接覆盖。具体采用方向加份数还是带符号数量、数量范围和请求标识格式，在正式契约中明确；无论格式如何，都只改变该规格当前可售数量，不修改订单占用，也不把订单占用计入可减少范围。首次创建规格仍按 FR-PRODUCT-003、FR-PRODUCT-004 填写初始库存，普通商品编辑不能成为绕过增减规则的全量覆盖入口。

服务端执行调整时需校验当前数量和归属，减少后不可为负，零变化不形成有效调整；成功响应应让页面取得最新可售量，失败不能部分修改。和下单、取消、超时、强制下架关闭或退款返还并发时，按服务端有效数据完成增减，不依据页面旧值回写。同一调整因重试或重复点击最多生效一次，农户明确发起的两次独立同额补货仍属于两次操作；请求去重、成功结果重放与状态冲突的响应需在后续契约中解释。调整原因是否必填等剩余细节仍待 Q-STOCK-001。

下架接口必须区分操作者及业务效果，不能只提供一个不说明影响的“切换上下架”动作：

| 场景 | 新购买与已有订单效果 | 接口设计必须表达的约束 |
| --- | --- | --- |
| 农户主动下架自己的商品，FR-PRODUCT-005 | 禁止新下单，购物车中不可继续购买，不再作为 AI 可购买候选；原有效未付款订单保留预占，仍可在原 30 分钟期限内按原金额支付 | 不因下架修改原截止时间、关闭订单或释放预占；支付不能只因当前商品已被农户主动下架而被拒绝，仍需校验订单本身状态和时效 |
| 管理员强制下架，FR-PRODUCT-006 | 禁止新下单，关闭包含该商品的未付款整单，返还整单全部明细预占 | 即使同单还有其他仍上架商品，也一起关闭并返还其占用；不拆单、不只移除下架商品明细；未付款关闭不产生退款，订单、明细和金额快照保留 |
| 两类下架对应的已付款订单 | 不自动退款或释放库存，继续原履约及发货前整单退款规则 | 不能借下架清除农户待审核、24 小时复核窗口、管理员待处理或超时待办仍存在的暂停发货限制 |

管理员强制下架关闭与支付竞争时，支付先有效完成则该单按已付款处理，不再关闭或释放；强制下架的付款限制或关闭先有效完成则后续付款被拒绝。即使后续设计采用异步批量关闭，也不能在强制下架已生效、订单尚未完成关闭的间隙放行付款。商品先前已经被农户主动下架，不代表管理员的强制下架可以跳过旧订单处理。

对同一订单的强制关闭、取消与超时重试需共同防止重复释放；同单含有多个被强制下架商品时，也不能按商品各返还整单一次。返还或人工增加库存不恢复商品上架；恢复权限、农户禁用及规格停用／移除仍另行确认。正式设计需说明下架处理结果、受影响订单、失败重试及新下单并发如何核对，不能仅以下架按钮返回成功代替订单处理已完成的证据。

业务状态、接口枚举与数据库状态必须对应。尚未确认的分支可以明确标记设计未完成，不能用含糊的“处理中”省略权限和操作边界。

## 5 AI 接口的重点约束

说明消息归属、会话 ID 校验、上下文范围、模型调用超时与失败结果，以及文本和商品卡片的数据结构。若采用流式返回，还需定义事件、结束信号、中断与重试，不能仅实现浏览器端后就认为微信端也可用。

模型工具只获得完成导购所需、当前调用者可访问的数据。工具参数与模型输出均需校验；商品卡片由后端核对，价格和库存以正常结算再次查询为准。发送消息必须登录，未登录时在任何模型调用前拒绝；首版不启用个人每日次数拦截。历史保留规则仍待 Q-AI-001，频率、单次消耗和预算见 Q-AI-002。

客户端不能指定任意中转地址、模型、系统指令或工具，把项目后端当作通用 API 代理。费用方案见 [AI 控费讨论稿](../architecture/AI导购与控费方案.md)：需设计内部模型调用的计数、用量记录、限额检查、超限响应，以及 usage 缺失或超时后的状态。具体额度与预算待 Q-AI-002，当前不预设数字或最终错误码。

## 6 接口完成与变更标准

接口可供开发前，应当具有上述字段说明、权限、状态、效果和例子，并能追踪到确认的 FR 与相关 AC；与未决问题相关的部分需明确标注，不声称已定稿。

实现后核对 Controller、参数校验、授权、Service 业务行为和实际响应与文档一致。修改路径、字段、校验、错误码或状态行为时同步更新契约、中文说明及受影响调用方；必要时说明已有数据和客户端如何兼容。
