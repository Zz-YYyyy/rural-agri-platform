# 接口文档

版本：V1 设计契约，2026-11-20。交付入口：微信小程序、H5、Vue 管理端，共用 Spring Boot 后端。

已形成首版已确认主流程的路径、方法、DTO、权限、错误与状态效果；**当前 dev 已实现并真实联调注册、登录、/me、退出四项操作；专用 MySQL 8.0／Redis 和 V1 已接通，其余业务接口尚未实现**。文档中的示例是演示输入输出，不是已运行结果。少量影响核心权限的未决分支见后文，不能把它们按普通 CRUD 自动放开。

## 2 通用 HTTP 与数据约定

- 所有路径已包含 `/api/v1`。契约的 server 为 `/`，部署时配置实际服务域名；不要再次拼接一层 `/api/v1`。微信真机和 H5 的可访问地址、HTTPS 与微信域名配置在部署阶段确定。
- 普通请求／响应为 UTF-8 JSON，请求头 `Content-Type: application/json`；图片上传为 `multipart/form-data`，由客户端自动生成 boundary，不手工写成不完整的固定 Content-Type。
- 成功通常 HTTP 200；AI 提问接受后 HTTP 202。成功外层统一 `code="OK" / message / data / traceId`，无额外数据时 `data={}`。不使用“HTTP 200 携带失败码”表示错误。
- 所有对象只允许 schema 定义的字段。ID 为正整数十进制字符串，金额为元的两位小数字符串，后端使用 BigDecimal。不能接受客户端指定操作者、订单状态、管理员标识或模型配置等未声明属性。
- 时间使用 UTC ISO 8601 毫秒形式，例如 `2026-11-20T02:00:00.000Z`；前端展示北京时间。业务时钟以服务端为准，客户端时间仅用于页面显示，不能提前结束窗口或延长付款期限。
- 普通分页为 `page=1 / pageSize=20`，最大100，成功 data 为 `items / total / page / pageSize`；无记录返回空数组和0。消息采用会话内序号游标，详见沟通模块，不能套用普通页码接口。
- 必填字段由 `required` 指定；可选字段未发生时可省略。只有明确 `nullable=true` 的字段接受 JSON null；修改类接口区分省略和清空，PUT 为对应 DTO 的完整替换，不等于替换整张数据库行。
- 普通文字以纯文字渲染，图文只允许白名单 text/image 块；公开响应使用可访问图片 URL，编辑输入使用上传服务签发的资源 key。上传归属和用途在保存业务对象时重新核对。
- 请求字符串做必要的首尾空白清理，密码不 trim；数据库字符长度和 Java 验证口径需统一。空白必填内容拒绝，不利用数据库默认值替用户勾选星级或完成支付。

成功示例（模拟）与错误示例：

```json
{"code":"OK","message":"成功","data":{},"traceId":"demo-trace-001"}
```

```json
{"code":"VALIDATION_ERROR","message":"参数校验失败","traceId":"demo-trace-001","fieldErrors":[{"field":"name","message":"名称不能为空"}]}
```

## 3 登录、角色与数据归属

| 权限标记 | 允许访问的身份 | 服务端检查 |
| --- | --- | --- |
| PUBLIC | 游客或登录用户 | 只返回当前可公开投影；带有效凭证可用于本人浏览去重，但不是必需条件 |
| MEMBER | 有效登录的平台账号 | 账号有效、JWT 签名与期限有效、Redis jti 会话仍存在；资源必须归本人 |
| FARMER | 当前账号具有有效农户身份 | 在 MEMBER 基础上从账号查询 farmer_id，并校验操作对象属于该农户 |
| ADMIN | 有效登录且 is_admin 为真 | 统一管理员角色；只执行契约明确授予的操作，不自动拥有所有数据修改或私密会话读取能力 |

本轮采用 2 小时 access JWT、不发 refresh token 的简化会话方案。Redis 保存 jti 会话与账号关联并设置对应过期；退出撤销当前 jti，其他设备会话不受影响。JWT 中的角色不能永久替代当前账号／经营状态校验。Redis 会话依赖不可用时，受保护请求返回503，不能只验签就降级放行。

退出的重复请求是明确例外：签名和有效期仍合法，但本 jti 已被撤销，返回退出成功；不得由这个例外放开其他接口。签名错误／已过期凭证按401处理。公开读取不因未携带或已失效的可选凭证而失去游客浏览能力，无效可选凭证按游客处理，不据其内容归属统计；受保护接口仍严格401。

管理员使用同一登录协议，管理端进入时查询 `/me` 的管理员能力。首个管理员通过后续明确的本地演示种子流程配置，不提供公开注册管理员或前端传 isAdmin 的入口。实际密码、微信 AppSecret、JWT 密钥和模型 Key 均由环境配置提供，不能写入契约或 Git。

微信登录仅兑换本项目配置 AppID 的一次性 code。已经绑定的平台账号可快捷登录；未绑定时引导注册／登录平台账号后首次绑定，不自动创建另一套账号。微信数量、换绑和解绑策略仍未确定，相应额外操作不开放。

私有资源不属于当前操作者时统一404，避免暴露其他用户对象是否存在；已登录但缺角色为403。管理员订单列表与详情使用独立脱敏 DTO，审核入驻只读取已有审核目的所需材料。聊天不提供管理员全量读取接口，公开农户资料不输出联系手机号。

## 4 错误与重试

| HTTP | 常见代码／含义 | 客户端处理 |
| --- | --- | --- |
| 400 | VALIDATION_ERROR 或具体参数错误 | 展示字段错误，修正输入后重新操作 |
| 401 | UNAUTHENTICATED／凭证失效 | 引导登录，保留适当页面选择；不要用默认账号代替用户 |
| 403 | FORBIDDEN、ACCOUNT_DISABLED 等 | 展示无权或受限说明，不重复调用 |
| 404 | NOT_FOUND 或目标不可见 | 展示不可用，不泄漏原正文或他人数据 |
| 409 | 状态、库存、报价、版本或幂等冲突 | 根据具体代码刷新对应数据；PRICE_CHANGED 必须让用户重新确认 |
| 413／415 | 图片过大／实际文件类型不支持 | 更换文件 |
| 429 | RATE_LIMITED | 按服务端 Retry-After 秒数稍后重试，不循环重发 |
| 500 | INTERNAL_ERROR | 展示 traceId 供排查，不返回堆栈、SQL 或密钥 |
| 503 | 依赖不可用、AI配置／预算不足、POLICY_PENDING | 展示原因；普通搜索仍可使用，未决分支不可绕过 |

具体错误码以各操作 `x-errors` 为准；表中是通用解释，不要求每条接口返回所有错误。服务端的401/403/404/400/500过滤器和异常处理也使用同一错误包络。`POLICY_PENDING` 表示设计未完成的特定分支，不代表数据库错误或可自动重试的模型调用。

关键提交通过 `Idempotency-Key` 标识一次用户动作，长度16～64，使用字母、数字、下划线或连字符。网络重试复用原键，用户主动新建另一轮操作使用新键。服务端在完成身份校验后先查原有效结果，再判断是否需要新操作；重复成功请求不能重复扣库存、退款、增加报名轮次或触发收费模型。

| 幂等方式 | 适用场景 | 保存及限制 |
| --- | --- | --- |
| 数据库唯一业务键 | 下单、退款申请、入驻、助农发布、库存和消息等 | 按操作映射现有 request_id/client_request_id/business_key/唯一关系；保存不可变原始摘要或原始输入，同键不同内容409 |
| 业务状态＋事件／版本 | 支付、发货、收货、退款处理、专题退出／解限等 | 成功事件与状态同事务写入；核对原对象／轮次／版本，不能让旧操作影响新一轮 |
| Redis 24小时防重 | 没有持久化创建键的普通新增 | key包含账号、operationId和幂等键；存原输入摘要和结果ID。崩溃造成结果不明时先读本人列表核对，不承诺跨崩溃严格一次 |
| 自然幂等 PUT／DELETE | 固定收藏、购物车目标数量、已读位置等 | 重复目标操作保持结果；不把“增加数量”伪装成可重复的目标赋值 |

管理员 `operation_id` 使用账号＋operationId＋幂等键的固定摘要，避免直接拼接超过数据库64字符。新增与审计同事务完成；失败事件不伪装成已发生成功修改。对旧成功请求的重放只返回当前授权可读的结果，不绕过后来的身份或可见性限制。

## 5 主要页面调用与实现顺序

| 页面／流程 | 调用与关键结果 |
| --- | --- |
| 首页、分类、搜索 | 分类树、地区选择、商品分页；首页组合专题／助农入口，不另建一套商品数据 |
| 商品详情、农户主页 | 公开资料与有效规格；农户评价使用匿名公开接口；咨询／收藏／购物前登录 |
| 入驻与农户商品 | 申请 → 管理员审核 → 经营资料 → 商品含规格创建 → 库存增减；首次审核外不建立逐条内容审核 |
| 助农专区 | 专题和主动助农信息分别查询；专题商品分页与报名关系独立；购买进入原商品订单 |
| 购物与售后 | 报价 → 比较确认单价／运费 → 建单预占 → 模拟付款 → 发货／退款 → 收货 → 整单评价 |
| 消息 | 读取会话 → 游标读取消息 → 显式推进本人已读位置；异步留言不要求双方在线 |
| AI | 读取入口能力 → 登录后建会话 → 提交提问 → 202后轮询原请求 → 展示核验卡片 |
| 管理后台 | 用各模块的管理员列表、审核、专题运营、评价可见性和退款操作；工作台组合已有待办与报表 |

建议先实现公共返回、鉴权与字典，再实现账号／入驻／商品和展示，随后助农内容、交易与沟通，最后接入付费 AI 与推广反馈。接口设计不要求前后端同时开始；可以先用契约示例开发页面，再接真实后端。

## 6 仍需补齐的实质分支

这份契约覆盖已确认主流程；下列分支保留明确边界，不将业务推测写成已获用户确认。带 `x-pending-policy` 的操作仍可实现其已确认正常情况，触及未决条件时返回 POLICY_PENDING 或不开放入口。

| 未决事项 | 对当前接口的影响 | 对应问题 |
| --- | --- | --- |
| 经营／账号禁用后的存量交易与咨询、解除限制后的恢复 | 本轮不增加全套禁用／恢复修改接口，不以原身份放行受限业务；已确认管理员强制下架及其订单效果仍独立实现 | Q-FARM-001、Q-ADMIN-001 |
| 退回入驻申请后的重提或待审修改撤回 | 首次提交与一次审核已定义，额外操作暂不开放 | Q-FARM-001 |
| 微信多绑定、换绑、解绑及账号找回 | 正常首次绑定／已绑定登录可实现；冲突不自动覆盖原关系 | Q-AUTH-001 |
| 已发布商品的规格新增／停用／删除、商品管理解除限制 | 现有规格价格名称及库存可改；未决操作不提供可执行路径 | Q-PRODUCT-001 |
| 条件不匹配参与的专题结束历史、隐藏状态下额外编辑／退出／提前结束 | 保存事实，已确认常规历史可读；命中特定未决分支时不猜纳入或排除 | Q-CAMPAIGN-001、Q-PROMO-001 |
| 隐藏评价私有正文／原因显示及首次回复 | 正常可见评价的本人订单入口保留，公开隐藏不重置次数；特殊私有展示按待定分支处理 | Q-REVIEW-001 |
| AI实际供应商、预算、token/工具上限、历史保留和清理 | API不接收客户端模型配置；未配置时不启动收费调用；不提供未经确定的历史删除或费用配置管理入口 | Q-AI-001、Q-AI-002 |

退款结束后的重申和提交前变价重确认已在本轮获得用户答复，现为 FR-REFUND-007、FR-ORDER-007，不再列为未决。

## 7 契约维护、生成与验证

源数据位于 `分模块契约/` 的公共定义及四个模块 JSON。它们使用标准 OpenAPI paths/components 结构，只有合并文件是可独立导入的完整契约。修改先改所属源文件和中文业务说明，再运行生成／校验命令；合并 JSON 与字段说明是生成产物，不另行手工维护第二份定义。

从仓库根目录运行（Python 3.10+，示例验证使用 jsonschema；不启动应用）：

```powershell
python scripts/build_api_contract.py --write
python scripts/build_api_contract.py
python scripts/check_database_design.py
```

检查覆盖重复路径／operationId、参数声明、内部引用、角色标记、FR/AC与表名映射、示例符合 DTO、生成文件同步。它是项目内契约检查，不是完整 OpenAPI 元 schema 校验器，也不证明 Swagger UI、真实 HTTP 或微信端已经通过；初始化工程后仍需导入工具核对、Controller实现对照和关键流程联调。

本轮对账时发现助农信息正文可编辑，原发布输入不能再由当前正文恢复，因此为仍在设计阶段、未执行的 V1 增加 `assistance_post.request_fingerprint`。现为29表405字段；SQL、字段字典与说明同步，不连接已有数据库。订单和退款原有摘要字段已能支持相应幂等契约。
