# 功能模块与主要页面总览

更新日期：2026-11-20。用途：看清项目全貌，按已有数据库和接口设计推进基础工程及模块开发。

本稿收拢已有需求，不替代 [需求正文](需求文档.md) 和 [决策记录](../项目决策记录.md)。模块功能依据既有确认；页面归并、技术落点与交付顺序属于实施安排，不表示已经开发或验证。普通增删改查与常规参数在设计时直接落实，低优先级边界不再逐题讨论。

## 1 项目要完成什么

让用户发现乡村特色农产品、了解产地和农户，能咨询、选购；让农户维护商品、主动推广、参与专题并查看推广反馈。后台负责首次入驻审核、内容运营与必要管理，AI 帮助用户查找和比较平台商品。

助农展示围绕“发现产品 → 了解产地与种植者 → 咨询或选购 → 查看推广反馈”展开。支付、退款和物流均为模拟演示，浏览与咨询反馈不等于真实增收。

| 入口／角色 | 使用方式 | 能完成的主要事情 |
| --- | --- | --- |
| 游客与普通用户 | uni-app 微信小程序、在线 H5 | 游客先浏览；登录后收藏、购物、留言、评价、使用 AI 和申请入驻 |
| 农户 | 同一小程序／H5 中的农户中心 | 初次入驻通过后维护商品、推广、销售订单及咨询；保留普通购物能力 |
| 管理员 | 独立 Vue 3 网页管理端 | 统一管理角色，审核入驻、运营专题和产地内容、处理已确认管理事项 |

微信开发者工具运行演示是交付要求。小程序与 H5 共用业务数据，登录和分享适配各自平台；不用另做一个农户网页管理系统。

## 2 首版八个功能模块

这是产品功能分组，不强制对应八个微服务、八个数据库或八张表。

| 模块 | 用户侧 | 农户／管理侧 | 主要依据 |
| --- | --- | --- | --- |
| 账号与农户入驻 | 注册登录、微信绑定、个人资料；申请成为农户 | 最小入驻资料、审核结果、经营资料和固定运费；管理员首次审核 | FR-AUTH-001、FR-ROLE-001、FR-FARM-001 至 FR-FARM-004 |
| 农产品展示 | 首页、分类与搜索、商品详情、规格价格库存、所属农户 | 农户发布编辑、上下架及库存增减；管理员商品与分类管理 | FR-REGION-001、FR-PRODUCT-001 至 FR-PRODUCT-006、FR-INV-002 |
| 助农推广与特色内容 | 助农专题、主动助农信息、产地介绍、农户主页与故事 | 管理员组织专题与维护产地；农户报名专题、发布助农信息、维护故事；本人／管理员查看推广反馈 | FR-PROMO-001 至 FR-PROMO-033、FR-CONTENT-001 |
| 购物与模拟交易 | 购物车、按农户结算、模拟付款、取消、确认收货及发货前退款 | 农户销售订单、模拟发货、退款处理；管理员退款复核与超时接手 | FR-CART-001、FR-SHIP-001、FR-SHIP-002、FR-ORDER-001 至 FR-ORDER-006、FR-INV-001、FR-REFUND-001 至 FR-REFUND-007 |
| 咨询与购买评价 | 异步文字留言、未读提示；完成订单后整单评价 | 农户回复咨询及评价；管理员隐藏／恢复评价或回复 | FR-COMM-001、FR-COMM-002、FR-REVIEW-001 至 FR-REVIEW-008 |
| 个人中心与常用资料 | 我的订单、收藏、收货地址、消息、账号设置及 AI 入口 | 通过“我的”进入入驻申请或农户中心 | FR-UI-002、FR-AUTH-001、FR-ORDER-004；[个人页面](页面与导航说明.md) |
| AI 导购 | 用自然语言找商品、连续追问、查看推荐理由和商品卡片 | 后端查询平台数据并校验结果，控制调用频率与消耗 | FR-AI-001 至 FR-AI-007 |
| 后台管理与运营 | 用户通过公开内容看到运营结果 | 用户／农户管理、商品管理、专题与产地内容、订单售后、评价管理、推广汇总及重要操作日志 | FR-ROLE-001、FR-PRODUCT-006、FR-PROMO-003；[管理页面](页面与导航说明.md) |

农户中心和管理后台聚合相关模块的操作，复用同一套商品、订单与推广数据。个人资料、收藏、地址的页面归并与普通管理交互在设计时落实，不扩展积分、会员或社交关注体系。

## 3 主要页面怎样组织

### 小程序与 H5

底部固定为 **首页／分类／助农／购物车／我的**。正常启动先到首页；分享链接进入对应公开详情，需要个人操作时再登录。

| 入口或页面组 | 核心内容与跳转 |
| --- | --- |
| 首页 | 搜索、分类及特色商品入口，助农内容入口，醒目的 AI 导购卡片；具体排列按页面设计落实 |
| 分类与搜索 | 按分类、关键词等条件找商品，进入商品详情 |
| 助农 | 管理员组织的专题与农户主动助农信息；详情可进入商品或农户主页 |
| 商品与农户／产地详情 | 看商品规格及来源，了解农户与种植故事；收藏、咨询、加入购物车或购买；评价集中在农户主页 |
| 购物车与交易页 | 按农户分组，确认订单、模拟支付、订单详情、退款及评价；结果和表单可复用组件 |
| 我的 | 订单、收藏、地址、资料设置、消息、AI，以及入驻或农户中心入口 |
| AI 导购 | 介绍、对话和推荐商品卡片；发送消息要求登录，选购仍进入正常商品流程 |
| 消息 | 会话列表、文字消息及未读提示，双方不必同时在线 |

上述为页面组，不要求每个操作独立占一页。详情、表单、弹窗和组件拆分由实现确定；不为普通布局反复确认。

### 农户中心

保留六组入口：**工作台、商品管理、助农推广、订单售后、咨询消息、经营资料**。

- 商品管理：商品列表、发布编辑、规格与库存、上下架。
- 助农推广：我的助农信息、发布编辑、专题报名与参与管理、自己的图文故事、推广反馈。
- 订单售后：销售订单、详情、模拟发货、退款处理、买家评价的一次回复。
- 工作台汇总已有入口和必要待办；经营资料维护入驻后的公开介绍与运费，咨询复用留言能力。

### 网页管理端

按业务设置 **工作台、用户与农户、商品与分类、产地与专题、订单与退款、评价管理、推广反馈、操作日志**。管理端以列表、筛选、详情和必要操作为主；统计只展示有明确定义、实际可采集的数据，不额外建设复杂报表系统。

商品、资料、助农内容和合规专题报名不逐条预审；首次入驻与已有退款处理仍按确认规则执行。管理操作范围以需求正文为准，不能因统一管理员角色就任意修改所有数据。

## 4 答辩需要跑通的主流程

1. **农户供给**：注册登录 → 申请入驻 → 管理员审核 → 农户发布带规格的商品 → 用户端能浏览。
2. **助农推广**：管理员发布专题 → 农户用合格商品报名；农户也能独立发布助农信息 → 用户了解专题、产地和农户 → 进入商品或发送咨询 → 农户查看浏览、咨询反馈。
3. **购物履约**：选规格 → 加车或立即购买 → 按农户创建订单并预占库存 → 模拟付款 → 农户模拟发货 → 用户确认收货 → 整单评价与农户回复。
4. **取消与退款**：未付款取消／超时关闭释放库存；已付款未发货申请整单退款 → 农户处理；已有争议复核流程按需求实现。重点核对金额、库存与发货权限一致。
5. **异步沟通**：用户给农户发文字问题 → 农户稍后查看回复 → 用户看到回复和未读变化，不依赖双方同时在线。
6. **AI 选购**：登录后输入预算或产品需求 → AI 调用后端商品查询 → 返回经过校验的商品卡片与理由 → 追问或进入商品选购。

开发先连通这些流程，再补齐已确认的其他操作。未确认边界在涉及模块设计时处理，不表示演示成功就已完成全部验收。

## 5 每项技术落在哪里

| 技术 | 首版实际用途 | 可验证的结果 |
| --- | --- | --- |
| uni-app／Vue 3 | 用户和农户页面、路由、表单、状态及接口调用，适配微信与 H5 | 两端能访问同一后端并操作核心流程 |
| Vue 3 管理端 | 管理列表、筛选、表单、权限入口及基础统计展示 | 管理操作能改变业务数据和前台展示 |
| Spring Boot | REST 接口、分层业务、鉴权校验、事务和定时处理 | 下单与库存一致；超时关闭、自动收货等按既有规则执行 |
| MySQL 8.0 | 账号、商品规格、订单、推广、留言等持久化；关联、索引及约束 | 数据归属明确，重启后保留，订单快照与当前商品分开 |
| Redis | 常用读取缓存与请求限流，配合会话及 AI 近期上下文 | 缓存更新可验证，异常高频请求受控，不替代订单库存的持久化依据 |
| Spring AI＋模型 API | 商品查询工具、多轮导购、结果校验与用量控制 | 有依据的商品推荐、上下文追问、费用保护及异常降级 |
| 工程配套 | OpenAPI、版本化 SQL、必要测试、构建配置及部署说明 | 文档可联调，数据库可初始化，微信开发者工具及在线入口可验收 |

后端优先按业务分包的单体结构。框架版本在初始化时核对兼容性；配套依赖按已有技术方向落实。RAG、向量数据库、微服务、消息队列等不作为首版必需项，不为体现技术另加模块。

数据与接口继续相互校准；不会把普通字段逐项交给用户选择。常规实现由开发决定，真正影响范围、核心权限、金额或主要状态的差异再集中讨论。接口源定义维护在 `docs/api/分模块契约/`，经 `scripts/build_api_contract.py` 生成合并契约和字段说明；修改方式见接口文档，不能只更新生成结果或把静态检查当作 HTTP 联调。

本轮数据设计采用农户主页一份 JSON 图文故事、一个地区一份产地介绍、同一用户与农户归并留言会话；推广反馈先按 UTC 的 30 分钟桶去重浏览，并统计带有效来源的买家咨询消息。这些是为完成首版作出的实施设计，不是补写历史用户确认；具体结构和指标定义以数据库实现说明为准，不引入文章社区或即时通讯。

微信 AppID／绑定测试条件、模型平台与费用预算、正式在线演示资源在相应接入阶段落实；当前不请求密钥、不调用收费模型，也不假定已有部署条件。

当前范围继续遵守：独立采购意向单后置；内容互助任务、农户 AI 宣传助手首版暂不做；优惠、积分、优惠券及活动报名未纳入。原消费者 AI 导购保留，普通购买与批量询问沿用商品订单和站内留言。
