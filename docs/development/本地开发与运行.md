# 本地开发与运行

更新日期：2026-11-20。本文包含基础启动与账号开发入口；专用服务、凭据、迁移与账号调用链见 [独立数据库与账号联调](独立数据库与账号联调.md)。正式业务行为仍以需求、接口和数据库文档为准。基础页面与 HTTP 公共组件不等于已经实现购物、入驻或 AI 导购。

## 1 中文路径与编码

当前仓库位置为 `D:\1.MYDEV\1毕设\code`。本轮保持该目录，直接在这里安装依赖、编译和启动检查；具体结果见文末验证记录。工程使用 UTF-8，源码目录、Java 包名及 npm 包名使用英文，`docs/` 内的中文文档名称保留。

中文路径是否兼容取决于实际使用的工具和脚本，不能仅凭目录含中文就认定无法开发，也不能承诺所有未来插件都支持。遇到问题先区分编码、依赖版本、命令引号和路径本身。命令中的路径使用引号；辅助脚本通过自己的位置定位仓库，不硬编码本机盘符。未来若确认某工具不支持，再迁移到短英文路径，并重新安装依赖、更新 IDE 和微信项目位置。

中文文档名和程序运行目录是两个问题。无需为消除构建问题把说明文档全部改为英文，也不要把个人绝对路径写进业务代码或配置。

## 2 环境与依赖管理

| 工具 | 本次本机环境 | 使用方式 |
| --- | --- | --- |
| Java | 17.0.12 | 项目编译目标 Java 17，源码与资源为 UTF-8 |
| Maven | 3.9.11 | 后端依赖由 `pom.xml` 管理 |
| Node.js | 24.14.1 | 根 `.node-version` 记录本次基线，不修改系统安装 |
| npm | 11.11.0 | 两个前端分别维护 `package-lock.json`，后续使用 `npm ci` |
| PowerShell | 7.6.9 | `scripts/dev.ps1` 与 `scripts/check.ps1` 要求 PowerShell 7+ |
| Python | 3.10+；接口检查另需 `jsonschema` | 仅供文档契约检查，不是业务服务依赖 |

管理端与 uni-app 各自安装依赖，不在仓库根目录创建混用版本的前端依赖树。uni-app 的编译器、Vue 和 Vite 需作为配套组合升级，不能只把其中一项改成 `latest`；各端确切版本以自己的 `package.json` 和锁文件为准。

后端选用 Spring Boot 3.5.16、MyBatis-Plus Boot 3 starter 3.5.18、springdoc 2.10.0，预留 Spring AI 1.1.8 BOM。Spring AI 目前只管理未来依赖版本，没有创建模型客户端、读取 Key 或发送收费请求。MySQL 驱动、Flyway、Redis 和测试基础依赖跟随 Boot 的依赖管理。

uni-app 当前稳定模板组合存在已知依赖审计项，详见 [验证记录](../testing/基础工程验证记录.md)。本阶段保持本机开发使用，部署前需完成兼容修复与复测，不能将构建成功解释为依赖安全审查通过。

版本选择依据为 [Spring Boot 3.5 系统要求](https://docs.spring.io/spring-boot/3.5/system-requirements.html)、[Spring AI 官方兼容说明](https://github.com/spring-projects/spring-ai#readme)、[DCloud CLI 指南](https://uniapp.dcloud.net.cn/quickstart-cli)、[Vue 快速开始](https://cn.vuejs.org/guide/quick-start)及实际发布包。这里记录的是本项目验证的组合，后续升级仍需重新构建两端与后端。

## 3 首次安装与启动

在 PowerShell 中进入仓库：

```powershell
Set-Location 'D:\1.MYDEV\1毕设\code'
npm --prefix frontend/admin ci
npm --prefix frontend/miniapp ci
```

随后分别打开终端启动需要的工程；脚本以前台方式运行，使用 `Ctrl+C` 停止：

```powershell
pwsh -NoProfile -File scripts/dev.ps1 -Target backend
pwsh -NoProfile -File scripts/dev.ps1 -Target admin
pwsh -NoProfile -File scripts/dev.ps1 -Target h5
```

| 工程 | 默认访问位置 | 当前用途 |
| --- | --- | --- |
| 后端 | `http://127.0.0.1:8080/actuator/health` | 默认 bootstrap 模式，只检查 HTTP 基础服务；返回 UP 不代表数据库或业务已可用 |
| 管理端 | `http://127.0.0.1:5173` | 管理员登录与受保护布局，业务模块仍为骨架 |
| H5 | `http://127.0.0.1:5174` | 游客首页、注册登录与我的，其他业务页逐步接入 |

`/actuator/health` 属于运行维护端点，不纳入业务 `/api/v1` 契约，也不包裹为业务 DTO。业务请求和错误按既有契约设计，未实现的业务不能因为健康检查通过就作为可调用功能。

两个前端的 `/api` 本地代理指向后端。接口封装支持统一响应和 HTTP 错误，不会自动生成登录身份。管理端现在先登录并通过 /me 核对管理员能力才进入布局；后端逐次校验当前身份，其他业务接口尚未开放。默认服务用于本机开发，真机访问需单独配置网络地址。

## 4 微信开发者工具

```powershell
pwsh -NoProfile -File scripts/dev.ps1 -Target weixin
```

CLI 监视构建输出到 `frontend/miniapp/dist/dev/mp-weixin`。微信开发者工具导入该输出目录，不能直接把整个仓库当成原生小程序工程导入。发布构建命令为：

```powershell
npm --prefix frontend/miniapp run build:mp-weixin
```

发布输出为 `frontend/miniapp/dist/build/mp-weixin`。CLI 编译通过和微信工具中运行是两个独立检查；还需要在本机配置自己的小程序 AppID，并在微信工具中打开和验证。AppSecret 不放到前端，小程序 code 换取身份由后端实现。

H5 本地代理不会自动作用于微信小程序。微信端调用后端需要配置它实际可访问的完整服务地址；手机中的 `127.0.0.1` 指向手机本身。开发工具内的本地调试与真机／正式 HTTPS 域名要求分开处理，不能以 H5 可访问替代微信端验收。

小程序配置变量为 `VITE_API_BASE_URL`（H5 可使用 `/api/v1`，微信端需完整可访问的 HTTP(S) 地址）、`VITE_DEV_PROXY_TARGET`（H5 开发代理目标）和 `VITE_WECHAT_APP_ID`。AppID 仅写入忽略的构建输出，未配置时 DCloud 输出 `touristappid`；该占位不是已绑定的真实小程序。示例见 [小程序工程入口](../../frontend/miniapp/README.md)；只提交 `.env.example`，真实本地配置使用被 Git 忽略的 `.env.local` 等文件。管理端代理变量为 `DEV_PROXY_TARGET`，与小程序变量名称区分。

## 5 后端运行模式与基础设施

默认 `bootstrap` 模式不创建数据库／Redis 连接，不运行 Flyway，也不创建演示管理员。此模式用于验证编译、HTTP、安全错误格式及健康检查；bootstrap 业务路由仍拒绝访问；dev 已按契约开放四项基础账号接口。

显式 `dev` 模式为基础设施集成预留以下环境配置：

| 变量 | 用途 |
| --- | --- |
| `SPRING_PROFILES_ACTIVE=dev` | 启用开发基础设施配置 |
| `DB_URL`、`DB_USERNAME`、`DB_PASSWORD` | 专用开发数据库连接信息；不复用未核实的现有业务库 |
| `REDIS_HOST`、`REDIS_PORT`、`REDIS_PASSWORD`、`REDIS_DATABASE` | Redis 连接，是否需要密码以实际实例为准 |
| `DB_MIGRATE_ENABLED` | 默认 false；仅在已确认的专用空库中显式开启迁移 |
| `SERVER_PORT`、`SERVER_ADDRESS` | 本地端口与监听地址，默认 8080 和 127.0.0.1 |

本机现已按 D-087 准备独立 MySQL 8.0.46（13306）和 Redis（16379），原有 MySQL 9.4 保留。运行 `scripts/local-services.ps1 -Action start` 后，使用 `scripts/dev.ps1 -Target backend -UseLocalServices` 载入被 Git 忽略的本地配置。JWT 密钥是 dev 的必填配置；全部变量、路径、数据持久化与迁移不可变要求见 [独立数据库与账号联调](独立数据库与账号联调.md)。

Springdoc 生成页面只反映当前已写出的 Controller；完整计划契约仍在 [接口文档](../api/接口文档.md)。bootstrap 运行时页面无业务接口，dev 页面反映当前四项账号接口；均不替代完整设计契约。

## 6 检查与产物

从仓库根目录运行：

```powershell
# 文档检查需先具备 jsonschema
python -m pip install jsonschema
pwsh -NoProfile -File scripts/check.ps1
```

也可使用 `-Scope docs`、`backend`、`admin` 或 `miniapp` 单独检查。脚本调用文档静态检查、Maven verify、前端类型检查和构建；任一步失败即停止，不把后一步成功误当成整体成功。它不自动启动数据库、导入数据或调用模型。

| 产物 | 位置 | 是否提交 Git |
| --- | --- | --- |
| 后端 jar 与测试结果 | `backend/target/` | 否，由 Maven 重新生成 |
| 管理端静态文件 | `frontend/admin/dist/` | 否，由构建生成 |
| H5 与微信编译文件 | `frontend/miniapp/dist/` | 否，由构建生成 |
| 前端依赖锁文件 | 各端 `package-lock.json` | 是，用于复现依赖 |
| 本地密码与 AppID 等配置 | 各工程 `.env.local` 或系统环境 | 不提交真实本地配置 |

MySQL 8.0／Redis 与注册登录已接通，下一阶段实现农户入驻与商品展示主流程；付费模型和正式部署在对应阶段配置。
