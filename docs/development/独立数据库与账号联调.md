# 独立数据库与账号联调

更新日期：2026-11-20。关联 FR-AUTH-001、FR-ROLE-001、D-087。本文记录本机专用开发实例和第一批账号接口；完整业务范围仍见需求与接口文档，执行结果见 [账号与基础设施验证记录](../testing/账号与基础设施验证记录.md)。

## 1 本机实例

用户已确认为本项目另外准备 MySQL 8.0 与 Redis，保留现有服务。本轮未改动已有 MySQL 9.4 的安装、服务、配置及数据库，未向其执行 SQL，也未安装新的系统自启动服务或修改全局 PATH。

| 项目 | 本轮配置 |
| --- | --- |
| 独立服务根目录 | `D:\1.MYDEV\rural-agri-local`，在代码仓库外 |
| MySQL | Community Server 8.0.46 ZIP，`127.0.0.1:13306` |
| 专用库与应用用户 | `rural_agri_dev`、`rural_agri_app@127.0.0.1` |
| Redis | redis-windows 社区 Cygwin 构建 8.10.3，`127.0.0.1:16379`，database 0 |
| 连接限制 | 两者仅监听本机回环地址，均配置随机密码 |
| 应用账号权限 | 仅专用库的开发／Flyway 所需权限，不使用 root 运行后端 |
| 数据目录 | 服务根下 `data/mysql` 与 `data/redis` |
| 日志目录 | 服务根下 `logs` |
| 二进制目录 | 服务根下 `tools/mysql/mysql-8.0.46-winx64`、`tools/redis/Redis-8.10.3-Windows-x64-cygwin` |
| 下载归档 | 服务根下 `downloads`；保留供核对和重装，不属于业务数据 |

MySQL 来源为 [Oracle 官方下载页](https://dev.mysql.com/downloads/mysql/8.0.html)，ZIP 的 MD5 已与官方公布的 `003f527d5df61b663ff191038cd676bd` 一致。Redis 来源为 [redis-windows 8.10.3 发布页](https://github.com/redis-windows/redis-windows/releases/tag/8.10.3)，所用 Cygwin ZIP 的 SHA-256 为 `8000848C48668C8CD32F21386CE951D0E02C1AEFAE39443AB9D3DE11FF8EBF9E`，已核验。

这是 **Redis 的社区 Windows 移植版**，不是 Redis 官方原生 Windows 安装包。本机未安装 Docker 或完整 WSL，本轮不为开发环境开启系统虚拟化功能。该实例用于本地账号会话和限流验证，后续 Linux 部署使用相应官方 Redis 发行版并重新验证兼容性。

Redis 启用 AOF `everysec` 和 RDB；停止脚本使用 `SHUTDOWN SAVE`。这只是本地持久化设置，不代表已经完成备份、恢复或生产高可用方案。MySQL 使用 utf8mb4、UTC 与严格 SQL 模式。

本轮安装后按文件长度统计：MySQL 二进制约 933.81 MiB、Redis 二进制约 37.97 MiB、MySQL 数据约 199.44 MiB、下载归档约 250.64 MiB，合计约 1.39 GiB；Redis 数据和配置日志当前很小。数据与日志会随使用增长，此数字不是文件系统实际分配空间或后续固定容量；没有为每个前端复制一份数据库工具。

## 2 启动与停止

在仓库根目录运行 PowerShell 7 命令：

```powershell
# 后台启动专用数据库与 Redis；重复启动只检查原实例
pwsh -NoProfile -File scripts/local-services.ps1 -Action start
pwsh -NoProfile -File scripts/local-services.ps1 -Action status

# 单独终端，启动真实账号后端；Ctrl+C 停止后端
pwsh -NoProfile -File scripts/dev.ps1 -Target backend -UseLocalServices

# 另外两个终端按需启动
pwsh -NoProfile -File scripts/dev.ps1 -Target h5
pwsh -NoProfile -File scripts/dev.ps1 -Target admin

# 后端停止后，正常关闭本项目基础服务，保留数据
pwsh -NoProfile -File scripts/local-services.ps1 -Action stop
```

`local-services.ps1` 支持 `-Target mysql|redis|all`。它核对监听端口、进程可执行文件路径和回环地址；端口由其他进程占用时直接报错，不按端口强杀进程。脚本仅启动／停止已经准备好的专用实例，不初始化或清空数据目录，不操作 Windows 服务列表。状态 `ready=True` 表示通过带认证的 MySQL 查询或 Redis PING。

MySQL 和 Redis 后台运行，关闭启动终端不等于关闭它们；Windows 重启后需再次执行 start。服务二进制和本地配置被移动时，须同步下节的本地路径。

不加 `-UseLocalServices` 的后端命令仍采用原 `bootstrap`：不连接 MySQL／Redis，不开放账号业务。真实注册登录联调必须使用 dev 配置；不要因为 bootstrap 健康检查成功就判断账号接口已经可用。

## 3 本地配置与迁移

实际连接密码、JWT 密钥保存在仓库 **被 Git 忽略的** `runtime/local-env.json`；本地 root 客户端配置在服务根的 `config/mysql-root.ini`，服务配置为 `config/mysql.ini` 与 `config/redis.conf`。请在本机编辑器中查看，不将内容贴到聊天、截图、日志或提交到仓库。

`runtime/local-env.json` 包含以下结构，示例仅说明形状，**不能原样作为凭据使用**：

```json
{
  "serviceRoot": "D:/your-local-services",
  "mysqlRoot": "D:/your-local-services/tools/mysql/mysql-8.0.46-winx64",
  "redisRoot": "D:/your-local-services/tools/redis/Redis-8.10.3-Windows-x64-cygwin",
  "mysqlConfig": "D:/your-local-services/config/mysql.ini",
  "mysqlClientConfig": "D:/your-local-services/config/mysql-root.ini",
  "redisConfig": "D:/your-local-services/config/redis.conf",
  "environment": {
    "SPRING_PROFILES_ACTIVE": "dev",
    "DB_URL": "jdbc:mysql://127.0.0.1:13306/rural_agri_dev?connectionTimeZone=UTC&forceConnectionTimeZoneToSession=true&allowPublicKeyRetrieval=true&sslMode=DISABLED",
    "DB_USERNAME": "rural_agri_app",
    "DB_PASSWORD": "<本机随机密码>",
    "DB_MIGRATE_ENABLED": "true",
    "REDIS_HOST": "127.0.0.1",
    "REDIS_PORT": "16379",
    "REDIS_PASSWORD": "<本机随机密码>",
    "REDIS_DATABASE": "0",
    "JWT_SECRET_BASE64": "<至少32个随机字节的Base64>",
    "JWT_ISSUER": "rural-agri-platform",
    "JWT_AUDIENCE": "rural-agri-platform"
  }
}
```

连接串关闭 TLS 仅用于当前本机回环开发实例；不能复制为远程部署的安全配置。另一台机器须自行准备隔离实例及本地配置，Git 拉取不会带出本机数据库、密码或安装包。本轮没有提交一键重置数据库或默认密码脚本。

`dev.ps1 -UseLocalServices` 将 environment 中变量载入启动进程，不打印变量值，不写入机器级环境变量。后端退出后恢复启动脚本进程原环境。

当前专用数据库初次为空，允许 `DB_MIGRATE_ENABLED=true` 由 Flyway 执行 V1。再次正常启动时，Flyway 校验已执行版本，仅应用新增迁移，不能重新执行 V1 建表。V1 一旦实际应用就保持不变；后续表结构变更增加 V2 等文件。不要直接把配置指向已有业务库，也不要用 clean／repair 消除未知迁移错误。数据库共有 29 张业务表，另有 Flyway 自身历史表。

## 4 已接入的账号链路

| 接口 | 行为 |
| --- | --- |
| `POST /api/v1/auth/register` | 创建普通 ACTIVE 账号，返回账号资料，注册不自动登录 |
| `POST /api/v1/auth/login` | 验证密码和账号状态，签发 accessToken，保存独立 Redis 会话 |
| `GET /api/v1/me` | 先验 JWT 与 Redis 会话，再查询数据库当前身份 |
| `POST /api/v1/auth/logout` | 只撤销本次 token 的 jti，其他设备会话保留 |

这些接口使用已有 JSON 契约与统一响应，成功 HTTP 200；完整 DTO、字段与错误码见 [账号与商品接口](../api/账号与商品接口.md)。未实现的业务路由仍默认拒绝；这四项可运行不表示全部 137 项设计操作已实现。

后端调用链为 `AuthController → AuthService → AccountRepository → AccountMapper → MySQL`。注册密码使用 BCrypt cost 10，只保存哈希。用户名去首尾空白并转小写，4～32 字符、英文字母开头，允许字母数字下划线；密码原样保留，8～72 字符并额外检查 UTF-8 不超过 72 字节；昵称去首尾空白后 1～40 字符。不接受客户端提交 isAdmin、农户状态或任意未知字段。

JWT 使用 HS256，期限 7200 秒，无 refresh token。`JWT_SECRET_BASE64` 必须解码为至少 32 个随机字节，缺失或无效时 dev 启动失败，不回退到内置密钥。JWT 包含 sub、jti、iss、aud、iat、exp；签名、签发方、接收方、有效期均校验，不能只解码信任。

Redis 会话键为 `rural-agri:auth:session:<jti>`，值为账号 ID，TTL 对齐 JWT 到期。受保护请求通过 `BearerSessionFilter` 校验会话，并查询当前账号和农户状态；角色不以客户端缓存或旧 token 为准。退出后旧 token 不能读取 `/me`；同一个签名正确、未过期的已退出 token 可再次退出，重复退出不影响其他会话。Redis 不可用时返回 503，不放行仅验签的请求。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `AUTH_REGISTER_PER_MINUTE` | 5 | 每来源 IP、60 秒窗口注册请求上限 |
| `AUTH_LOGIN_IP_PER_MINUTE` | 30 | 每来源 IP、60 秒窗口登录请求上限 |
| `AUTH_LOGIN_ACCOUNT_PER_MINUTE` | 10 | 每规范化账号、60 秒窗口登录请求上限 |
| `PUBLIC_BASE_URL` | `http://127.0.0.1:8080` | 生成默认头像 URL；真机／部署时设置实际可访问地址 |

以上限流是当前账号模块的可配置技术值，**不是 AI 每日额度**，不改变 AI“不设个人每日固定次数”的已确认规则。Redis 原子窗口累加、首次设置过期；超限返回 429 与 Retry-After。当前直接连接取 remoteAddr，不盲信客户端 X-Forwarded-For；未来 Nginx 部署需配置可信代理后再验证客户端 IP。

## 5 前端使用与验收边界

H5／微信页面共享账号密码登录和注册表单。游客仍可进入首页和五个导航；“我的”提供登录入口。注册成功返回登录页；成功登录后读取 `/me` 才展示当前身份。本地持久化 token 与到期时间，角色资料不作为可信缓存保存；重开应用需服务端复核。旧请求的 401 或延迟响应不能覆盖新登录状态。退出失败会清理本机凭证并告知服务端撤销尚未确认，不显示虚假的全部退出成功。

管理端所有业务页面需要有效登录且 `/me.isAdmin=true`；普通账号登录凭据正确也不能进入管理工作区。管理端 token 放 sessionStorage，刷新重新校验，关标签后的保存行为与小程序持久化不同。没有管理员注册入口、默认管理员或固定密码；首个长期管理员的受控创建在管理模块阶段落实，不通过本轮测试临时账号充当用户可用管理员。

微信端目前使用同一账号密码流程。原生微信 code 换取身份、微信绑定尚未实现；AppID、AppSecret 与开发者工具实测仍单独配置和验收。H5 和微信 CLI 构建通过不能代替开发者工具实际运行。

商品、入驻审核、专题、订单、留言和 AI 暂未实现，本轮不调用收费模型。已有 uni-app 依赖审计问题继续见 [基础工程验证记录](../testing/基础工程验证记录.md)，不能因新增登录就宣称已经达到公网部署条件。
